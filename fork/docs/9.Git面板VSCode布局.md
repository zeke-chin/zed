# 9. Git 面板 VS Code 式布局

> 本仓库是 zed-industries/zed 的个人 fork。整体设计见 `0.整体设计.md`。

## 目标

上游 Git 面板把 Changes 和 History 做成两个标签页，提交信息编辑器在底部。这个功能把它改成 VS Code 源代码管理视图的样子：

```
┌──────────────────────────────────────┐
│ ▾ CHANGES (3)   Uncommitted▾ ± ⚙ Stage All▾ │ 分区标题：大写加粗，可折叠
│ ┌──────────────────────────────── ✦ ┐ │
│ │ 提交信息（单行起步，最多 10 行）   │ │ 输入框：界面字体、圆角边框、聚焦高亮
│ └────────────────────────────────────┘ │
│ [        ✓ Commit         | ▾ ]        │ 整宽主按钮，右侧是 Amend/Signoff 菜单
│ 改动文件列表                           │
├──────────────── 可拖动 ────────────────┤
│ ▾ GRAPH                 Fetch▾  [图]   │
│ ○ 最新提交  作者           (✓ main)(☁) │ 单行：连线、标题、作者、分支/标签徽标
│ ● 更早提交  作者                        │
└──────────────────────────────────────┘
```

## 设置

```json
{
  "git_panel": { "dock": "left" },
  "fork": {
    "git_panel": { "layout": "vscode" }
  }
}
```

- `fork.git_panel.layout`：`"tabs"`（默认，上游布局）或 `"vscode"`。改了立即生效，不用重启。
- 面板放在左边用的是上游自己的 `git_panel.dock`，不归 fork 管。

## 实现

代码在 `crates/git_ui/src/git_panel/fork_vscode_layout.rs` 和 `fork_vscode_layout/graph.rs`（挂钩 H12）。它是 `git_panel` 的子模块，可以直接用 `GitPanel` 的私有字段和渲染函数，不用复制上游代码。`git_panel.rs` 里只有挂钩 H11 那几行。

- **复用上游部件**：Changes 列表（`render_entries`）、改动模式菜单、视图选项、Stage All、生成提交信息按钮、提交菜单、Fetch/Push 按钮都直接调用上游函数。fork 自己画的只有分区标题、输入框外框、Commit 按钮外形和历史行。
- **提交输入框**：和上游共用同一个 `commit_editor`。VS Code 布局下每帧把它的模式调成 `AutoHeight { min_lines: 1, max_lines: 10 }`，切回 `tabs` 时恢复上游的固定 6 行；`ToggleFillCommitEditor` 展开时不干预。字体用界面字体，不用 buffer 字体。
- **历史连线**：`fork_vscode_layout/graph.rs`。每行单独画（VS Code 的做法）：车道一旦分配就不挪位置，每行只需要知道穿过的车道、汇入提交点的车道和从提交点出发的车道。第一个父提交总留在本车道，其余父提交复用已有车道或开新车道。数据来自与历史列表同一份 `graph_data` 缓存（历史条目里只有 SHA，父提交和 ref 从这里取），历史列表每次重新加载时重算。超过 6 条车道的部分裁掉，保证标题有地方显示。
- **分支徽标**：`HEAD -> x` 和当前分支排第一，用 ✓ 图标；远程分支和同名本地分支在同一提交时缩成一个云图标；标签用书签图标。最多显示 2 个，其余收进 `+n`。未推送的提交末尾加 ↑。
- **`active_tab` 的含义不变**：两块同时显示后，`active_tab` 表示「键盘在哪个列表里」。点到哪一块就切到哪一块（`capture_any_mouse_down`），上下键、回车、`ChangesList`/`HistoryList` 键位上下文都沿用上游逻辑。`ActivateHistoryTab` 在历史折叠时会先展开。
- **历史加载**：上游只在 History 标签激活时加载和刷新历史。H11 把这些判断换成 `fork_history_is_shown`：VS Code 布局下看历史区是否折叠，否则仍看标签页。折叠或切回 `tabs` 时释放历史数据和订阅，与上游切走标签页时的做法一致。
- **分隔条**：历史区顶部 4px 的拖动条，拖动时在正文上用 `on_drag_move` 算出历史区高度；双击恢复默认的 40%。面板太矮时历史区先被压缩，Changes 保持最小高度。
- **提交区展开**（`ToggleFillCommitEditor`）时只显示提交区，和上游一致。
- 不显示上游的仓库/分支行和「上一次提交」行：分支在标题栏里，Fetch/Push 移到 GRAPH 标题右侧，撤销提交在历史行的右键菜单里。
- 工作区干净时 Changes 下面留空（VS Code 也是这样），不显示上游的「No changes to commit」占位。

## 没做的

- 折叠状态和分隔条高度只保存在内存里，重启后恢复默认。
- 历史只包含当前分支（`git log <branch>`），和上游 History 标签一致；所有分支的完整图点 GRAPH 标题右侧的按钮在编辑区打开。
- 历史行不显示头像和时间，时间、作者和短 SHA 放在悬浮提示里。
- 没加到设置界面（Settings UI），只能在 `settings.json` 里改。

## 测试

`fork_vscode_layout::tests`：

- VS Code 布局下不切标签也会加载历史。
- 折叠后历史被释放、键盘回到 Changes；`ActivateHistoryTab` 重新展开并加载；切回 Changes 历史保留。
- 切回 `tabs` 布局时释放隐藏的历史，再切回来重新加载。
- 渲染后提交框在 Changes 区顶部、历史在下面，折叠后 Changes 占用让出的空间。
- `graph::tests`：线性历史只占一条车道；合并提交开出侧车道，并在共同父提交处汇合。
