# 9. Git 面板 VS Code 式布局

> 本仓库是 zed-industries/zed 的个人 fork。整体设计见 `0.整体设计.md`。

## 目标

上游 Git 面板把 Changes 和 History 做成两个标签页，提交信息编辑器在底部。这个功能把它改成 VS Code 源代码管理视图的样子：

```
┌──────────────────────────────────────┐
│ ▾ CHANGES (3)   Uncommitted▾ ± ⚙ Stage All▾ │ 分区标题：大写加粗，可折叠
│ ┌──────────────────────────────── ✦ ┐ │
│ │ 提交信息（单行起步，最多 10 行）   │ │ 输入框：界面字体、圆角边框、聚焦高亮
│ └────────────────────────────────────┘ │
│ [        ✓ Commit         | ▾ ]        │ 整宽主按钮，右侧是 Amend/Signoff 菜单
│ ▾ Tracked          ⤓ ± ↶ +  (1)       │ 分组标题：悬浮显示暂存/查看/放弃/暂存全部，数量徽标
│   Dockerfile   +2 −0  ⇥ ↶ +  M        │ 文件行：增删行数、悬浮显示打开/放弃/暂存，状态字母
├──────────────── 可拖动 ────────────────┤
│ ▾ GRAPH                 Fetch▾  [图]   │
│ ○ 最新提交  作者           (✓ main)(☁) │ 单行：连线、标题、作者、分支/标签徽标
│ ● 更早提交  作者                        │
└──────────────────────────────────────┘
```

## 设置

```json
{
  "git_panel": { "dock": "left" },
  "fork": {
    "git_panel": { "layout": "vscode" }
  }
}
```

- `fork.git_panel.layout`：`"tabs"`（默认，上游布局）或 `"vscode"`。改了立即生效，不用重启。
- 面板放在左边用的是上游自己的 `git_panel.dock`，不归 fork 管。
- `fork.git_panel.show_tags` / `show_remote_branches`：GRAPH 里是否显示标签、远程分支徽标，默认都是 `true`。GRAPH 标题右侧的筛选按钮可以直接切换，会写回用户设置。
- `fork.git_panel.graph_page_size` / `graph_page_on_scroll`：GRAPH 分页，见下面「GRAPH 分页」一节。

## 实现

代码在 `crates/git_ui/src/git_panel/fork_vscode_layout.rs` 和 `fork_vscode_layout/graph.rs`（挂钩 H12）。它是 `git_panel` 的子模块，可以直接用 `GitPanel` 的私有字段和渲染函数，不用复制上游代码。`git_panel.rs` 里只有挂钩 H11 那几行。

- **复用上游部件**：Changes 列表（`render_entries`）、改动模式菜单、视图选项、Stage All、生成提交信息按钮、提交菜单、Fetch/Push 按钮都直接调用上游函数。fork 自己画的只有分区标题、输入框外框、Commit 按钮外形和历史行。
- **提交输入框**：和上游共用同一个 `commit_editor`。VS Code 布局下每帧把它的模式调成 `AutoHeight { min_lines: 1, max_lines: 10 }`，切回 `tabs` 时恢复上游的固定 6 行；`ToggleFillCommitEditor` 展开时不干预。字体用界面字体，不用 buffer 字体。
- **历史连线**：`fork_vscode_layout/graph.rs`。每行单独画（VS Code 的做法）：车道一旦分配就不挪位置，每行只需要知道穿过的车道、汇入提交点的车道和从提交点出发的车道。第一个父提交总留在本车道，其余父提交复用已有车道或开新车道。数据来自与历史列表同一份 `graph_data` 缓存（历史条目里只有 SHA，父提交和 ref 从这里取），历史列表每次重新加载时重算。超过 6 条车道的部分裁掉，保证标题有地方显示。
- **分支徽标**：`HEAD -> x` 和当前分支排第一，用 ✓ 图标；远程分支和同名本地分支在同一提交时缩成一个云图标；标签用书签图标。最多显示 2 个，其余收进 `+n`。未推送的提交末尾加 ↑。
- **`active_tab` 的含义不变**：两块同时显示后，`active_tab` 表示「键盘在哪个列表里」。点到哪一块就切到哪一块（`capture_any_mouse_down`），上下键、回车、`ChangesList`/`HistoryList` 键位上下文都沿用上游逻辑。`ActivateHistoryTab` 在历史折叠时会先展开。
- **历史加载**：上游只在 History 标签激活时加载和刷新历史。H11 把这些判断换成 `fork_history_is_shown`：VS Code 布局下看历史区是否折叠，否则仍看标签页。折叠或切回 `tabs` 时释放历史数据和订阅，与上游切走标签页时的做法一致。
- **分隔条**：历史区顶部 4px 的拖动条，拖动时在正文上用 `on_drag_move` 算出历史区高度；双击恢复默认的 40%。面板太矮时历史区先被压缩，Changes 保持最小高度。
- **Changes 列表的行内按钮**（VS Code 的 inline actions）：H11 在上游 `render_list_header`、`render_status_entry`、`render_directory_entry` 里各加一个挂钩，VS Code 布局下用 fork 渲染的按钮替换数量 Chip 和勾选框，点击、拖动、右键菜单仍是上游的。
  - 分组标题：`Stash All Changes`（Tracked/Unstaged）、`Open Changes`（Tracked 打开整体 diff，Staged/Unstaged 打开暂存区/工作区 diff）、`Discard All Changes`（Untracked 组是 `Trash All Untracked Files`）、`Stage All`/`Unstage All`（Tracked/Untracked 全部已暂存时变成 −），最后是数量徽标。按钮悬浮时显示，组为空时不显示。
  - 文件行：增删行数（受上游 `git_panel.diff_stats` 控制，放在按钮左边，按钮出现时不移动）、`Open File`、`Discard Changes`（已删除文件是 `Restore File`，未跟踪文件是 `Trash File`）、`Stage`/`Unstage`，最后是状态字母 `M`/`A`/`U`/`D`/`!`（冲突）。按钮在悬浮或选中时显示。左侧上游的状态图标不再显示，由字母代替。
  - 分组名换成 VS Code 的：`Staged Changes`、`Changes`、`Untracked Changes`、`Merge Changes`。Staged/Unstaged 组为空时数量显示 0。
  - **分组方式**：VS Code 布局下上游的 `git_panel.group_by: "status"`（默认）当作 `"staging"`（挂钩 H13），暂存后文件移到 `Staged Changes`，未跟踪文件在 `Changes` 里显示 `U`，和 VS Code 一致。视图选项菜单里的「Tracked & Untracked」此时隐藏；`"none"`（不分组）仍然有效。
  - 树状视图的目录行：`Discard Changes`、`Stage`/`Unstage`。
  - 行内按钮作用于被点的行；该行在多选里时作用于整个多选，和右键菜单一致。确认弹窗、冲突已解决后不能取消暂存等规则都沿用上游函数（`revert_selected`、`stage_selected`/`unstage_selected`、`revert_entries`）。
  - `Open File` 图标 Zed 没有，放在 `assets/icons/fork/go_to_file.svg`（新文件）。
  - 分支模式（Branch Changes）不能暂存，仍用上游的样子。
- **刷新 git 状态**：Zed 平时靠文件事件发现 `.git` 的变化。`.git` 是指向工作区外的软链接时，macOS 报的事件是真实路径，和 Zed 监听的软链接路径对不上，暂存、提交后状态不会更新（按状态分组时勾选框靠待完成操作立刻打勾，看不出来；按暂存状态分组时文件不会移组）。做法照 VS Code：面板自己的暂存/取消暂存、全部暂存、提交、放弃改动完成后重新读一次状态（H11）；窗口重新获得焦点时刷新，能读到在外部终端里执行的 git 命令；VS Code 布局下 Git 面板获得焦点（切到面板、从编辑器或内置终端点进面板）时也刷新，能读到在 Zed 内置终端里执行的命令；CHANGES 标题右侧加 ↻ 刷新按钮。重新读状态用的是上游的 `schedule_scan`，由 H14 的 `Repository::fork_rescan` 公开出来。这几处刷新在 `tabs` 布局下也生效。
- **提交区展开**（`ToggleFillCommitEditor`）时只显示提交区，和上游一致。
- 不显示上游的仓库/分支行和「上一次提交」行：分支在标题栏里，Fetch/Push 移到 GRAPH 标题右侧，撤销提交在历史行的右键菜单里。
- 工作区干净时 Changes 下面留空（VS Code 也是这样），不显示上游的「No changes to commit」占位。

## GRAPH 分页

### 问题

历史一次显示当前分支的全部提交，连线宽度取所有已加载提交的最大车道数（上限 6）。只要很久以前有一段并行分支多的历史，整列就被撑到 6 条宽，顶部大多只用 1～2 条车道，左边空出一大块。

### VS Code 的做法（已核对源码）

- `scm.graph.pageSize`：默认 50，范围 1～1000，既是首屏条数，也是每次多加载的条数。
- `scm.graph.pageOnScroll`：默认 `true`，底部的加载行一渲染（即滚到底）就加载下一页；关掉后底部是一行 `Load More...`，点击加载，加载中图标换成转圈。
- 加载行只在最后一条提交还有父提交（下面还有历史）时出现。
- VS Code 的连线宽度是**每行单独算**的（`scmHistory.ts`：`SWIMLANE_WIDTH * (max(入车道数, 出车道数, 1) + 1)`），所以它本身没有「整列被撑宽」的问题，分页主要是为了性能。这里不照搬按行宽度，因为标题左边缘会参差不齐；宽度仍取**已显示提交**的最大车道数。

### 设置

```json
{
  "fork": {
    "git_panel": {
      "graph_page_size": 50,
      "graph_page_on_scroll": false
    }
  }
}
```

- `fork.git_panel.graph_page_size`：首屏显示多少条提交，也是每次「Show More」多显示的条数。默认 `50`，小于 1 按 1 算。
- `fork.git_panel.graph_page_on_scroll`：滚到底时是否自动加载下一页。默认 `false`，即底部显示「Show More」按钮，要点才加载。
- 只影响 VS Code 布局的 GRAPH；`tabs` 布局的 History 标签不变，仍显示全部。

### 实现

- **限制条数的位置**：在上游的 `fetch_commit_history_entries` 里截断（扩展 H11），VS Code 布局下只把前 `history_limit` 条放进 `commit_history`。这样键盘上下移动、右键菜单、`active_history_entry_index` 等上游逻辑看到的就是已显示的那些，不用再逐处判断范围。`tabs` 布局下不截断。
- **状态**：`LayoutState` 加 `history_limit: usize`（初始为 `graph_page_size`）、`history_has_more: bool`（`git log` 拿到的提交多于 `history_limit`）和 `history_source`（`history_limit` 是按哪个仓库和日志来源算的，变了就回到第一页）。
  - 点「Show More」：`history_limit += graph_page_size`，再调一次 `fetch_commit_history_entries`。`git log` 的结果已经在 `graph_data` 缓存里，加载是同步的，不需要转圈状态。`fork_show_more_history` 带上发起时的页数，页数已变就不再加，同一页的请求重复到达（自动加载的行一帧内可能布局多次）只加一页。
  - 重置为 `graph_page_size`：历史被释放时（折叠 GRAPH、切回 `tabs`，即 `fork_unload_commit_history`），以及切换仓库或当前分支时。新提交、Fetch 等引起的刷新保持当前条数。
  - 改 `graph_page_size` 设置：同上重置并重新取。
- **连线**：`fork_sync_graph` 现在要求缓存里的提交和历史条目一一对应（`commits.len() == entries.len()`），改成「历史条目是缓存的前缀」，只对前 `entries.len()` 条调 `compute_rows`。车道是从上往下推算的，只算前 N 条得到的每一行和算全部时完全一样，不会画错。顺带的好处：现在每次刷新都在前台线程对整个仓库的全部提交重算车道，改后只算已显示的那些。
- **宽度**：沿用现有逻辑（已显示提交的最大车道数，上限 6）。点「Show More」后新的一页车道更多时，整列会变宽，这是接受的行为。
- **「Show More」行**：`history_has_more` 为真时，`uniform_list` 多一行，高度和提交行相同（24px）。左边空出连线列宽度，右边是一个小号、次要颜色的「Show More」按钮（带向下图标）。
  - `graph_page_on_scroll = true` 时这一行只显示文字不显示按钮，并在它被渲染（滚到可见）时用 `cx.defer` 加载下一页，避免在渲染回调里直接改状态。
  - `git log` 还在流式返回（`is_loading`）时，如果已拿到的提交还不到 `history_limit`，不显示这一行，等数据到齐后再判断。
- **代码位置**：除 `fetch_commit_history_entries` 里一行 `// FORK:` 挂钩外，都在 `fork_vscode_layout.rs`；设置字段加在 `crates/settings_content/src/fork.rs` 的 `ForkGitPanelSettingsContent`，读取放在 `ForkGitPanelLayoutSettings`。

### 测试

`fork_vscode_layout::tests`：

- 提交数多于 `graph_page_size` 时只显示前 N 条，`history_has_more` 为真；「Show More」后变成 2N 条，同一页重复请求只加一次；最后一页显示完后不再有「Show More」。
- 提交数不超过 N 时没有「Show More」行。
- 折叠再展开、改 `graph_page_size` 后条数回到第一页；`tabs` 布局的 History 仍显示全部。
- 连线只对已显示的提交计算。
- `graph::tests`：对同一份历史，只算前 N 条得到的行和全部计算结果的前 N 行相同。

切换分支回到第一页靠 `history_source` 比较，测试用的 FakeFs 不方便切分支，没有单独测。

### 不在这次范围

- 键盘上下移动到最后一条时不会选中「Show More」行，回车也不能加载更多，只能用鼠标点或开 `graph_page_on_scroll`。
- 「Show More」行左边不画延续的连线（VS Code 会画），第一版留空。

## 没做的

- 折叠状态和分隔条高度只保存在内存里，重启后恢复默认。
- 历史只包含当前分支（`git log <branch>`），和上游 History 标签一致；所有分支的完整图点 GRAPH 标题右侧的按钮在编辑区打开。
- 历史行不显示头像和时间，时间、作者和短 SHA 放在悬浮提示里。
- 没加到设置界面（Settings UI），只能在 `settings.json` 里改。

## 测试

`fork_vscode_layout::tests`：

- VS Code 布局下不切标签也会加载历史。
- 折叠后历史被释放、键盘回到 Changes；`ActivateHistoryTab` 重新展开并加载；切回 Changes 历史保留。
- 切回 `tabs` 布局时释放隐藏的历史，再切回来重新加载。
- 渲染后提交框在 Changes 区顶部、历史在下面，折叠后 Changes 占用让出的空间。
- `graph::tests`：线性历史只占一条车道；合并提交开出侧车道，并在共同父提交处汇合。
