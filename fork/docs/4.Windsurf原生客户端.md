# 4. Windsurf 原生客户端

> 本仓库是 zed-industries/zed 的个人 fork。整体设计见 `0.整体设计.md`。

## 目标

在 `fork_windsurf` 里用 Rust 实现直连云端的 Tab 客户端，不依赖官方 LS。完成后在 Zed 里能看到修改预测和跳转预测，按 Tab 接受。

本阶段把整条链路打通，上下文只提供必需的几类；全部上下文在阶段 5 补齐。

前置：阶段 1 完成；阶段 2 的结论是原生方案可行。本文档里的协议细节以 `fork/spike/结论.md` 为准，两者冲突时改本文档。

## 模块

```
fork_windsurf/src/
  fork_windsurf.rs       # init、全局实体、对外入口
  delegate.rs            # EditPredictionDelegate 实现
  backend.rs             # TabBackend 接口
  native/
    auth.rs              # api_key、短期令牌的换取与刷新
    connect.rs           # Connect 协议的流式请求与分帧
    get_tab.rs           # GetTab 请求组装与响应解析
  context/               # 本阶段：active_document、diagnostics、other_documents
  trajectory.rs          # 本阶段：只有当前文档步骤和编辑步骤
  diff.rs                # DeltaTab 转成 Zed 的编辑
  proto/                 # prost 生成的消息定义
  status.rs              # 状态栏项
```

## 要做的事

### 4.1 proto

- 把阶段 2 提取的 proto 裁剪到 `GetTab` 用到的消息，放进 `fork_windsurf/proto/`。
- 用工作区已有的 `prost` / `prost-build` 生成 Rust 类型。
- 记录 proto 对应的官方 LS 版本号，写在模块顶部。

### 4.2 凭据

一个存放位置（用户 `settings.json` 的 `fork.windsurf.api_key`），两种写入方式，设计见 `0.整体设计.md` 第 8.1 节。

- 客户端只从 `ForkSettings` 读密钥，并且只取用户级设置的值，忽略项目级设置里的同名字段。
- 动作 `windsurf: import api key`（从本机导入）：按阶段 2 结论的位置读本机 Devin/Windsurf 的登录数据，找到后用 `update_settings_file` 写入用户设置，并提示来源和打码后的密钥；找不到时说明原因并引导手动填写。
- 动作 `windsurf: open api key setting`（手动填写）：打开用户设置文件；字段不存在时先写入一个空的 `fork.windsurf.api_key`。
- 字段里已有值时，导入先确认再覆盖。
- 读本机登录数据的代码只有导入动作这一个调用点，不在启动时或后台执行。
- 如果云端需要短期令牌：`auth.rs` 用 `api_key` 换取，只存在内存里，过期前刷新，刷新失败时按认证错误处理。
- 密钥和令牌不写日志，不进入遥测；界面提示里只显示打码后的值。
- 设置文件里的密钥变化后立即生效，不需要重启 Zed。

### 4.3 Connect 流式客户端

- 基于仓库的 `http_client` 实现 Connect 协议的服务端流：请求编码、响应按帧解析、结束帧里的错误处理。
- 每个请求有超时。同一编辑器发出新请求时取消还没结束的旧请求，并关闭连接。
- 错误分类：认证失败、限流、网络错误、协议错误（解不出来）。各自有不同的处理和状态栏提示。
- 限流和网络错误时退避重试，最长间隔 1 分钟；认证失败不重试。

### 4.4 `GetTab` 请求

- `metadata` 和固定字段按阶段 2 结论填写，客户端标识类的值集中定义在一处。
- 上下文本阶段提供三类：
  - 当前文档：全文、光标、可见范围、语言、路径、工作区根目录。
  - 诊断：当前 buffer 的诊断，按与光标的距离排序，有数量上限。
  - 其他打开的文件：按最近访问排序，数量和总大小有上限。
- 轨迹本阶段只记录两种步骤：当前文档快照、对当前文档的编辑。
- 轨迹哈希和缓存：按阶段 2 弄清的规则实现。如果结论是「每次发全量可行」，本阶段先发全量，缓存留到阶段 5。
- 收到 `MissingInformation` 时按要求补发一次；连续两次仍然缺失就放弃本次预测并记日志。
- 位置换算严格按阶段 2 确认的单位。Zed 内部用字节偏移和 `Point`，换算集中在一个模块里并有单元测试。

### 4.5 响应转成编辑

- 累积流式的 `DeltaTab` 增量，`is_complete` 之后得到完整结果。
- `DeltaSupercomplete` 转成 `Vec<(Range<Anchor>, Arc<str>)>`：
  - 应用前校验旧文本与 buffer 当前内容一致，不一致就丢弃，不做猜测性修补。
  - 把整段替换收窄成最小编辑（字符级 diff），纯插入显示为灰字，修改显示为 Zed 的 diff 预览。
  - 生成 `edit_preview`。
- `DeltaTabJump`：同文件时给出只带光标位置的预测；跨文件时通过 `Project` 预先打开目标 buffer，构造 `EditPrediction::Jump`。
- `DeltaNoop`：无预测。
- 是否在流式过程中就显示部分结果，看阶段 2 测到的增量间隔；默认等完整结果。

`diff.rs` 是纯函数，输入 buffer 文本和 `DeltaTab`，输出编辑列表，要有充分的单元测试。

### 4.6 Delegate

参考 `crates/codestral/src/codestral.rs` 实现 `EditPredictionDelegate`：

| 方法 | 行为 |
|---|---|
| `is_enabled` | 功能开启、有密钥、buffer 有磁盘路径 |
| `refresh` | 防抖后采集上下文并发请求；`trigger` 区分输入、光标移动、接受后等情况 |
| `suggest` | 把最近一次结果转成 `EditPrediction`，结果过期时重新定位或丢弃 |
| `accept` / `discard` | 记录反馈（阶段 5 上报），清掉当前结果 |
| `supports_jump_to_edit` | 由设置 `fork.windsurf.tab_jump` 决定 |

触发频率不高于官方客户端，防抖时间和并发数参考阶段 2 的流量记录。

### 4.7 接入与状态栏

- `fork_ext::assign_edit_prediction_provider`：`fork.edit_prediction_provider` 为 `"windsurf"` 且功能开启时，装上 `WindsurfDelegate` 并返回 `true`。fork 设置变化时对所有已打开的编辑器重新分配。
- 使用时官方设置写 `"edit_predictions": { "provider": "none" }`。两边同时配置了 provider 时以 fork 的为准，并在日志里提示一次。
- 状态栏项显示：未启用、未配置密钥、就绪、请求中、出错（含原因）。点击弹出菜单：开关、从本机导入密钥、填写密钥、打开日志。
- 调试动作 `windsurf: show last request`：在新标签页里显示最近一次请求的上下文摘要和服务端返回的提示词（`PreResponse.prompt`），密钥打码。这是对齐上下文时的主要工具。

## 待确认事项

- Zed 语言名到 Windsurf 语言枚举的映射表，未知语言的回退值。
- `EditPrediction::Local` 里 `PredictedCursorPosition` 怎么构造，接受后光标落点是否与响应里的 `cursor_position` 一致。
- 跨文件跳转需要目标 buffer 的快照，打开 buffer 是异步的，`suggest` 是同步的，要在 `refresh` 阶段预先打开。
- 远程项目（SSH）下文件路径是远端的。直连云端不依赖本机文件系统，理论上可以照常工作，需要实测。
- 仓库的 `http_client` 是否支持读取流式响应体而不整体缓冲。不支持的话评估替代办法，尽量不新增依赖。

## 不做的事

- 不做旧的经典补全 `GetCompletions`。
- 不做网页登录流程，密钥只通过导入或手动填写写入。
- 不做官方客户端的分析类上报，除非阶段 2 的结论是不发会影响预测。
- 完整的轨迹、检索、反馈上下文留给阶段 5。
