# 4. Windsurf 原生客户端

> 本仓库是 zed-industries/zed 的个人 fork。整体设计见 `0.整体设计.md`。

## 目标

在 `fork_windsurf` 里用 Rust 实现直连云端的 Tab 客户端，不依赖官方 LS。完成后在 Zed 里能看到修改预测，按 Tab 接受。

本阶段把整条链路打通，上下文只提供必需的几类；全部上下文、跳转预测（Tab Jump）、预测性预取在阶段 5 补齐。

> 阶段 2 结论（`fork/spike/结论.md`）对本文档的主要修正：跳转预测不在 `GetTab` 里，而是 LS 本地拼提示词调 `GetChatMessage`，挪到阶段 5；官方不发 `other_documents` 和检索结果，本阶段去掉「其他打开的文件」；当前文档和光标走 `command_intent_info`，不是轨迹步骤；响应不带位置，靠 `delta_old_str` / `delta_new_str` 文本定位。参照实现：`fork/spike/lib/tab_request.py`（`TabSession`）。

前置：阶段 1 完成；阶段 2 的结论是原生方案可行。本文档里的协议细节以 `fork/spike/结论.md` 为准，两者冲突时改本文档。

## 模块

```
fork_windsurf/src/
  fork_windsurf.rs       # init、全局实体、对外入口
  delegate.rs            # EditPredictionDelegate 实现
  backend.rs             # TabBackend 接口
  native.rs              # 声明下面的子模块
  native/
    auth.rs              # api_key → GetUserJwt → 15 分钟 user_jwt，过期前 60 秒刷新
    connect.rs           # Connect 协议：一元调用与服务端流、gzip 分帧、结束帧错误
    get_tab.rs           # GetTab 请求组装与响应累积
  context.rs             # 本阶段：command_intent_info（全文、光标、±5 行窗口）、诊断
  trajectory.rs          # 本阶段：CODE_ACTION 编辑步骤
  diff.rs                # old_str / new_str 转成 Zed 的编辑
  proto.rs               # include! prost 生成的消息定义
  credentials.rs         # 从本机导入 api_key（唯一读本机登录数据的地方）
  status.rs              # 状态栏项
fork_windsurf/proto/     # 从阶段 2 提取结果裁剪出的 .proto，build.rs 用 protox + prost-build 生成
```

## 要做的事

### 4.1 proto

- 把 `fork/spike/proto-out/proto/` 裁剪到 `GetUserJwt`、`GetTab`（含 `GetTabRequest/Response`、`DeltaTab`、`TabTrajectoryStepsV2`、`CortexTrajectory` 及用到的步骤类型、`Metadata`、`Document`、`Language`、`Model` 等）用到的消息，放进 `fork_windsurf/proto/`。为阶段 5 预留 `GetChatMessage`、`ProvideFeedback` 用到的消息。
- 生成方式和 `crates/proto` 一样：`build.rs` 里用 `protox::compile` + `prost_build::Config::compile_fds`，不需要本机装 `protoc`。
- 记录 proto 对应的官方 LS 版本号（LS 1.48.2，构建 `fcf7ba39`），写在 `proto.rs` 顶部。

### 4.2 凭据

一个存放位置（用户 `settings.json` 的 `fork.windsurf.api_key`），两种写入方式，设计见 `0.整体设计.md` 第 8.1 节。

- 客户端只从 `ForkSettings` 读密钥，并且只取用户级设置的值，忽略项目级设置里的同名字段。
- 动作 `windsurf: import api key`（从本机导入）：读 `~/Library/Application Support/Devin/User/globalStorage/state.vscdb`（SQLite，表 `ItemTable`，`key='windsurfAuthStatus'`，值是 JSON，取 `apiKey`），找不到再试 Windsurf 的同类路径，参照 `fork/spike/lib/import_key.py`；用工作区已有的 `sqlez` 读，只读打开。找到后用 `update_settings_file` 写入用户设置，并提示来源和打码后的密钥；找不到时说明原因并引导手动填写。
- 动作 `windsurf: open api key setting`（手动填写）：打开用户设置文件；字段不存在时先写入一个空的 `fork.windsurf.api_key`。
- 字段里已有值时，导入先确认再覆盖。
- 读本机登录数据的代码只有导入动作这一个调用点，不在启动时或后台执行。
- 云端需要短期令牌：`auth.rs` 用 `api_key` 调 `POST https://server.codeium.com/exa.auth_pb.AuthService/GetUserJwt`（一元，`application/proto`）换 `user_jwt`，15 分钟有效，过期前 60 秒重取。只存在内存里，刷新失败时按认证错误处理。每个 `GetTab` 的 metadata 里 `api_key` 和 `user_jwt` 都要带。
- 密钥和令牌不写日志，不进入遥测；界面提示里只显示打码后的值。
- 设置文件里的密钥变化后立即生效，不需要重启 Zed。

### 4.3 Connect 流式客户端

- 基于仓库的 `http_client` 实现 Connect 协议的服务端流：请求编码、响应按帧解析、结束帧里的错误处理。请求头对齐 LS（connect-go）：`User-Agent: connect-go/1.18.1 (go1.26.6)`、`Connect-Protocol-Version: 1`、`Connect-Timeout-Ms`、流式调用 `Content-Type: application/connect+proto` + 请求帧 gzip + `Connect-Content-Encoding: gzip` + `Connect-Accept-Encoding: gzip` + `Accept-Encoding: identity`；一元调用 `application/proto` + `Accept-Encoding: gzip`。
- 地址：`GetTab` 发往 `https://inference-us-west-lb.codeium.com`，其余发往 `https://server.codeium.com`；两者都做成可在设置里覆盖的内部常量（本阶段不加设置字段，集中定义在一处）。
- 每个请求有超时。同一编辑器发出新请求时取消还没结束的旧请求，并关闭连接。
- 错误分类：认证失败、限流、网络错误、协议错误（解不出来）。各自有不同的处理和状态栏提示。
- 限流和网络错误时退避重试，最长间隔 1 分钟；认证失败不重试。

### 4.4 `GetTab` 请求

- 必填：`metadata{api_key, user_jwt, ide_name="windsurf", ide_version, extension_version}`（其余字段按 LS 的样子填全，`f` 不填）、`provider_source=PROVIDER_SOURCE_SUPERCOMPLETE`、`model=MODEL_TAB_EXPERIMENTAL_4`、`unified_prompt_components.command_intent_info`、至少一个轨迹步骤。`streaming_completion_version=2`，`prompt_id` 每次一个 uuid，`chat_messages`、`experiment_config` 不填。客户端标识类的值（版本号、模型名、地址）集中定义在一处。
- 上下文本阶段提供两类：
  - 当前文档：`command_intent_info.input_document`（全文、`cursor_offset` 为 **UTF-8 字节**、`absolute_uri`、`workspace_uri`、`editor_language`、`line_ending`、`is_dirty`）；`selection` 是光标行 `[row-5, row+6)` 的原文，去掉窗口首尾空行、按文件边界截断，`selection_start_line` / `selection_end_line` 0 起、end 不含；`instruction`、`request_source=COMMAND_REQUEST_SOURCE_SUPERCOMPLETE` 按抓包填固定值。
  - 诊断：`code_diagnostics`，只取光标行 ±10 行内，最多 5 条。
- 轨迹本阶段只记录 `CODE_ACTION` 编辑步骤（行级 unified diff，变更行前后约 10 行上下文；某文件在轨迹里的第一步带 `original_content`）。连续输入合并成一步，触发时切分。`cortex_trajectory{trajectory_id, trajectory_type=SUPERCOMPLETE, parent_references=[会话主轨迹 id, USER_MAINLINE, step_index=-1]}`，每个编辑会话固定一个主轨迹 id。**没有任何编辑步骤时不发请求**（空轨迹云端回 internal error）。
- 本阶段每次发全量轨迹（阶段 2 实测可行）；哈希缓存留到阶段 5。
- 位置换算：只需要「Zed 光标 → UTF-8 字节偏移」和 0 起行号。Zed 内部本来就是字节偏移，换算集中在一个模块里并有单元测试（中文、emoji、CRLF）。

### 4.5 响应转成编辑

- 帧序固定：一条 `DeltaSupercomplete{delta_old_str}`（等于请求里的 `selection` 原文）→ `PreResponse{cache_info_v2}` → 若干 `DeltaSupercomplete{delta_new_str}` → `is_complete` → 带 `stop_reason` 的帧 → Connect 结束帧。把所有 `delta_old_str`、`delta_new_str` 分别按顺序累加到流结束。默认等完整结果再显示（首条增量到完成约 200 ms）。
- 响应**不带位置**（`start_line` / `end_line` / `cursor_position` 在本版本不出现）。转换成 `Vec<(Range<Anchor>, Arc<str>)>`：
  - 在请求时的 buffer 快照里，`old_str` 就是 `selection` 那几行；校验它与 buffer 当前内容一致，不一致就丢弃，不做猜测性修补。
  - 对 old / new 做字符级 diff（工作区已有 `similar`），收窄成最小编辑；old == new 表示无预测。纯插入显示为灰字，修改显示为 Zed 的 diff 预览，生成 `edit_preview`。
  - 过滤空操作、纯空白修改。
- 每帧带的 `path` 与当前 buffer 不一致时丢弃（跨文件留给阶段 5）。
- `DeltaTabJump`、`DeltaNoop`：本版本 `GetTab` 不返回跳转；收到 `DeltaNoop` 或解不出的增量按无预测处理。

`diff.rs` 是纯函数，输入 buffer 文本、窗口位置和 old / new 字符串，输出编辑列表，要有充分的单元测试。

### 4.6 Delegate

参考 `crates/codestral/src/codestral.rs` 实现 `EditPredictionDelegate`：

| 方法 | 行为 |
|---|---|
| `is_enabled` | 功能开启、有密钥、buffer 有磁盘路径 |
| `refresh` | 防抖后采集上下文并发请求；`trigger` 区分输入、光标移动、接受后等情况 |
| `suggest` | 把最近一次结果转成 `EditPrediction`，结果过期时重新定位或丢弃 |
| `accept` / `discard` | 记录反馈（阶段 5 进入轨迹并上报），清掉当前结果 |
| `supports_jump_to_edit` | 本阶段返回 `false`；阶段 5 实现 Tab Jump 后由设置 `fork.windsurf.tab_jump` 决定 |

触发频率不高于官方客户端：防抖后每个编辑器同时最多一个请求，新请求发出时取消旧请求。

### 4.7 接入与状态栏

- `fork_ext::assign_edit_prediction_provider`：`fork.edit_prediction_provider` 为 `"windsurf"` 且功能开启时，装上 `WindsurfDelegate` 并返回 `true`。fork 设置变化时对所有已打开的编辑器重新分配。
- 使用时官方设置写 `"edit_predictions": { "provider": "none" }`。两边同时配置了 provider 时以 fork 的为准，并在日志里提示一次。
- 状态栏项显示：未启用、未配置密钥、就绪、请求中、出错（含原因）。点击弹出菜单：开关、从本机导入密钥、填写密钥、打开日志。
- 调试动作 `windsurf: show last request`：在新标签页里显示最近一次请求的上下文摘要（请求 JSON，密钥和令牌打码）和响应摘要（累积的 old / new、stop_reason、耗时）。阶段 2 实测服务端的 `PreResponse.prompt` 是空的，不再依赖它。

## 待确认事项

- `EditPrediction::Local` 里 `PredictedCursorPosition` 怎么构造：响应不带光标位置，默认放在最后一处编辑的末尾。
- Zed 语言 → `Language` 枚举的映射表，未知语言回退 `LANGUAGE_UNSPECIFIED` 是否被云端接受。
- 远程项目（SSH）下文件路径是远端的。直连云端不依赖本机文件系统，理论上可以照常工作，需要实测。
- 仓库的 `http_client` 是否支持读取流式响应体而不整体缓冲。不支持的话评估替代办法，尽量不新增依赖。

## 不做的事

- 不做旧的经典补全 `GetCompletions`。
- 不做网页登录流程，密钥只通过导入或手动填写写入。
- 不做官方客户端的分析类上报（阶段 2：不发不影响预测）。
- 完整的轨迹（反馈、剪贴板步骤）、哈希缓存、跳转预测、预测性预取留给阶段 5。
