# 8. Windsurf 备选方案：LS 桥接

> 本仓库是 zed-industries/zed 的个人 fork。整体设计见 `0.整体设计.md`。
>
> 阶段 2 结论是走原生方案，本阶段暂不做。如果以后需要，补充两点（见 `fork/spike/结论.md` 问题 6–9、验收 7）：LS 要先收到 `RefreshContextForIdeAction`（STARTUP、ACTIVE_EDITOR_CHANGED、500 ms 防抖的 SELECTION_CHANGED）才开始记录编辑；云端报错时 LS 对 `HandleStreamingTabV2` 不响应，桥接要自己设超时。参照 `fork/spike/lib/ls_driver.py`。

## 定位

这是**退而求其次的方案**：不自己实现客户端，而是在本机拉起官方的 Language Server（LS）二进制，把上下文交给它，由它去调云端。

只在下面两种情况下做：

- 阶段 2 的结论是原生方案（直连云端）不可行。
- 原生方案已经完成，需要一个官方实现做并排对比，或者在云端协议升级后临时兜底。

## 与原生方案的对比

| | 原生方案（阶段 4、5） | LS 桥接 |
|---|---|---|
| 上下文采集、轨迹、检索 | 自己用 Rust 实现 | 官方 LS 完成，质量与官方一致 |
| 常驻进程 | 无 | 一个 LS 进程，有自己的索引和内存开销 |
| 链路 | Zed → 云端 | Zed → 本地 LS → 云端 |
| 协议升级 | 要自己跟进 | 换新版 LS 二进制即可，本地接口变化较少 |
| 依赖 | 无 | 需要本机有官方 LS 二进制 |
| 与官方客户端的差异 | 请求由自己构造 | 发往云端的请求由官方 LS 构造 |

## 复用的部分

`WindsurfDelegate`、状态栏、凭据、`diff.rs`、上下文采集器框架都与后端无关。本阶段只新增 `TabBackend` 的另一个实现 `LanguageServerBackend`，用设置 `fork.windsurf.backend` 切换。

如果是因为原生方案不可行才做本阶段，阶段 4 里与后端无关的部分（4.2 凭据、4.5 响应转编辑、4.6 Delegate、4.7 接入与状态栏）要在本阶段一并实现。

## 要做的事

### 8.1 LS 进程管理

- 定位二进制：先取设置 `fork.windsurf.language_server_path`，为空时在本机已装的 Devin/Windsurf 里找。不自动下载。
- 惰性启动：第一次需要预测时才启动；整个应用进程只启动一个，所有窗口共用。
- 启动参数、取端口的方式、心跳，按阶段 2 的最小验证结果。
- 退出清理：Zed 退出时结束 LS，不留孤儿进程。
- 崩溃恢复：LS 意外退出后，下一次请求时重启；连续失败时退避，最长间隔 1 分钟。
- 进程启动使用仓库现有的 `util::command` 封装。

### 8.2 请求

调用本地接口 `LanguageServerService/HandleStreamingTabV2`。IDE 侧要提供的原始上下文比云端请求简单：

| 字段 | 来源 |
|---|---|
| `document` | 当前 buffer 全文、光标、语言、路径、工作区根目录 |
| `other_documents` | 其他打开的 buffer |
| `diagnostics` | buffer 诊断 |
| `clipboard_entry` | 系统剪贴板 |
| `intellisense_suggestions` | 补全菜单候选，拿不到就不填 |
| `disable_tab_jump` | 设置 `fork.windsurf.tab_jump` 取反 |

这些字段直接复用阶段 4、5 的上下文采集器。

LS 自己维护编辑轨迹和索引，所以还要按阶段 2 抓到的 IDE → LS 流量，补上 IDE 平时会发的状态同步调用（例如文档打开、内容变化、工作区初始化）。缺了这些，LS 的轨迹和检索是空的，预测质量会下降。

### 8.3 响应

`HandleStreamingTabV2Response` 是三选一：`Diff`、`TabJump`、`NoOp`。转换成与原生后端相同的内部结果类型，后面复用 `diff.rs` 和 delegate。

### 8.4 反馈上报

按 IDE → LS 流量里的做法，上报接受和拒绝。

### 8.5 状态栏

LS 后端启用时，状态栏菜单多两项：重启 LS、显示 LS 版本和路径。找不到二进制时显示「未找到 Language Server」并提示配置路径。

## 验收标准

| # | 标准 | 验证方法 |
|---|---|---|
| 1 | `fork.windsurf.backend` 设为 `"language_server"` 后出现预测，Tab 接受正确；修改预测和跳转预测都可用 | 手动 |
| 2 | 官方 Devin/Windsurf IDE 没开的情况下功能正常 | 手动 |
| 3 | 在两个后端之间切换不需要重启 Zed，切走后 LS 进程退出 | 手动 + `pgrep` |
| 4 | Zed 退出后没有残留的 LS 进程；打开两个窗口只有一个 LS 进程 | `pgrep -fl language_server` |
| 5 | 手动杀掉 LS 后，继续输入能自动恢复 | 手动 |
| 6 | 找不到二进制、启动失败、凭据失效，状态栏各有明确提示，编辑器不卡顿 | 手动 |
| 7 | 状态同步调用已实现：连续编辑后，预测能体现之前的编辑模式 | 阶段 5 的评估场景 |
| 8 | 协议层有针对假 LS 的测试，覆盖正常、超时、返回错误 | `cargo test -p fork_windsurf` |
| 9 | 阶段 5 的评估场景在本后端下执行一遍，结果记入 `fork/eval/windsurf/结果.md` | 人工评估 |
| 10 | 两个后端都存在时，有一份延迟和内存的并排对比 | 实测记录 |
| 11 | 本阶段没有新增上游挂钩 | `fork/check-hooks.sh` |

## 待确认事项

- LS 是否需要绑定一个工作区目录启动；Zed 多窗口、多工作区时一个 LS 能否同时服务。不能的话改成每个工作区一个 LS。
- 远程项目（SSH）下文件在远端，本机 LS 读不到，这种情况下禁用 LS 后端。
- LS 的索引会占用多少内存和磁盘，是否有参数可以限制。

## 不做的事

- 不自动下载或更新 LS 二进制。
- 不做旧的经典补全 `GetCompletions`。
