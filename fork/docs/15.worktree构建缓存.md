# 15. worktree 构建缓存

> 本仓库是 zed-industries/zed 的个人 fork。整体设计见 `0.整体设计.md`。

## 问题

用户级 `~/.cargo/config.toml` 把 `build-dir` 设成 `.cache/{workspace-path-hash}`，每个 workspace 路径一个缓存目录：

- 主仓库和每个 `.agents/worktree/<名字>` 路径不同，缓存互不复用，新 worktree 从零编译。
- worktree 删掉后缓存留在 `.cache` 里没人清理；incremental 一直累积，主仓库的缓存涨到过 392G。
- 如果改成所有 worktree 共用一个目录，同时构建会互相等 cargo 的锁。

## 方案：母本 + APFS 克隆

```
.agents/worktree/_base/target    → .cache/zed-base   母本：专用 worktree，只用来编母本
.agents/worktree/<名字>/target/                      新建 worktree 时用 cp -c 从母本克隆，之后各编各的
target（主仓库）                 → .cache/zed-main   主仓库自己的 debug 和 release（fork/bundle.sh）
```

**母本不能用主仓库编。** worktree 在主仓库目录下面，cargo 从当前目录逐级往上读 `.cargo/config.toml`，数组配置会拼接：worktree 的 `rustflags` 是自己那份加主仓库那份，同样的参数出现两遍。编译结果一样，但 `rustflags` 参与单元哈希，主仓库编出来的产物 worktree 一个也用不上（实测：克隆主仓库缓存后 1073 个 crate 全部重编，`.fingerprint` 条目从 1395 翻倍到 2790）。`_base` 和其他 worktree 在同一层，读到的配置完全相同，哈希一致。

- `.cargo/config.toml`（进仓库）加 `[build] build-dir = "{workspace-root}/target"`：每个 workspace 用自己的 `target/`，覆盖用户级的哈希目录。CI 上这就是默认值，不受影响。
- 母本由 `.agents/worktree/_base`（分离 HEAD 的 worktree）维护，它的 `target` 是指向 `/Users/zeke/workspace/rust_work/.cache/zed-base` 的软链接；主仓库的 `target` 指向 `.cache/zed-main`（都是本机一次性设置，不进仓库）。
- 新建 worktree 时把母本的 `debug/` 用 `cp -c -R` 克隆到 worktree 的 `target/debug`。APFS 写时复制，几秒完成，刚克隆时几乎不占空间。
- worktree 的 `target/` 在 worktree 目录里（已被 `.gitignore` 忽略），`git worktree remove` 时一起删掉。

效果：

- 第三方依赖全部复用；工作区 crate 会重编，因为新 checkout 的源文件修改时间都比缓存新。
- 各 worktree 的缓存互相独立，可以并发构建，没有锁竞争。
- 磁盘占用是一份母本加每个 worktree 实际重编的部分（十几到二十多 G），worktree 删掉即释放。

## 脚本 `fork/worktree.sh`

```
fork/worktree.sh new <名字> [基准，默认 fork]   # git worktree add .agents/worktree/<名字> -b wt/<名字>，再克隆母本缓存
fork/worktree.sh cache <名字>                   # 给已有 worktree 补克隆母本缓存（target/debug 不存在时）
fork/worktree.sh rm <名字> [--force]            # git worktree remove，再 git branch -d wt/<名字>（未合并的分支保留并提示）
fork/worktree.sh base                           # 打印母本路径和大小
fork/worktree.sh base-update [基准，默认 fork]   # 把 _base 切到基准并 cargo build -p zed
```

- 在主仓库或任意 worktree 里运行都行，主仓库路径从 `git rev-parse --git-common-dir` 推出。
- 母本不存在（主仓库还没编过）时只建 worktree，提示从零编译。
- 基准提交里的 `.cargo/config.toml` 没有 `build-dir` 这一行时给出警告：那样的 worktree 仍会落到用户级的哈希目录。

## 维护

- fork 前进较多、`Cargo.lock` 变化后运行 `fork/worktree.sh base-update`，新 worktree 才能复用到新依赖。
- 母本里旧的依赖产物和 incremental 会累积。`fork/worktree.sh base` 看大小，太大时删掉 `.cache/zed-base` 里的内容再 `base-update`。
- 克隆出来的缓存和母本互不影响，删母本不影响已有 worktree。

## 本机一次性设置

```sh
cache=/Users/zeke/workspace/rust_work/.cache
mkdir -p $cache/zed-main $cache/zed-base
mv target/* $cache/zed-main/ && rmdir target   # 主仓库已有 target 时
ln -s $cache/zed-main target
git worktree add --detach .agents/worktree/_base fork
ln -s $cache/zed-base .agents/worktree/_base/target
fork/worktree.sh base-update
```
