# 13. 全局搜索侧边栏（VS Code 样式）

> 本仓库是 zed-industries/zed 的个人 fork。整体设计见 `0.整体设计.md`。

## 目标

上游的全局搜索（`pane::DeploySearch`，`cmd-shift-f`）会打开一个**标签页**，结果放在可编辑的 multibuffer 里，带上下文行。打开后会占掉整个编辑区，看不到当前正在读的代码。

这个功能新增一个**停靠在侧边栏的搜索面板**，样子和交互照 VS Code 的 Search 视图：

```
┌───────────────────────────────────┐
│ SEARCH              ↻  ≡  ⊟  ⧉   │ 标题行：刷新 / 清空 / 全部折叠 / 在编辑器中打开
│ ▾ ┌───────────────── Aa ab .* ┐ │ 查询框，右侧三个开关
│   └───────────────────────────┘ │
│   ┌ Replace             AB  ⊞ ┐ │ 可折叠替换框：保留大小写 / 全部替换
│   └───────────────────────────┘ │
│                               … │ 点 … 展开 include / exclude
│ files to include                 │
│ ┌──────────────────────────────┐ │
│ files to exclude                 │
│ ┌────────────────────────── ⚙ ┐ │ ⚙ = 包含 gitignore 的文件
│ 18 results in 8 files - Open in editor │
│ ▾ 📄 README.md  docs        (6) │ 文件行：图标、文件名、灰色目录、匹配数
│      …api/v1/share-preview/{id} │ 匹配行：单行片段，匹配处高亮
│ ▸ 📄 routes.py  src/…       (1) │ 已折叠
└───────────────────────────────────┘
```

上游的搜索标签页**保留不动**，面板上的「Open in editor」用同样的查询打开它，需要带上下文看或者直接改结果时还能用。

## 背景：上游的情况

- Discussion #50282（2026-02，57 赞）提的就是这个需求，官方没有回应。
- PR #56390「Add project search panel」（@adityasaini007，+1044 行）已经实现了侧边栏面板的大部分功能，2026-05 以「没有获得 staff buy-in」为由关闭，没有被审查过代码。
- 已合并的 #59604（`crates/search/src/text_finder.rs`）做的是 IntelliJ / Telescope 式的**弹窗**搜索，不是侧边栏，和这个功能不冲突。
- 官方拒过「VS Code 化」的 UI（#58868 activity bar），所以上游短期不会做，只能在 fork 里做。

## 做法：以 PR #56390 为底子

PR 的 diff 存档在 `fork/docs/explores/pr56390.diff`（`gh pr diff 56390` 取下，作为来源记录）。代码沿用它，提交信息里注明 `Based on zed-industries/zed#56390 by @adityasaini007`。

### PR 里直接沿用的部分

- 面板骨架：`Panel` trait 实现、`load`、dock 位置和尺寸、`ToggleFocus`。
- 搜索执行：直接调 `project.search(query)`，按 256 条一批流式收结果，用 `search_id` 丢弃过期结果。**不复用上游的 `ProjectSearch` 模型**，面板和标签页互不影响，合并上游时也少一个耦合点。
- 查询构造：文本、正则、大小写、整词、包含 ignored、include/exclude glob，以及出错时输入框变红。
- `DeploySearch` 参数的处理（查询文本、各开关、include/exclude）。
- 点击匹配：在当前 pane 打开文件，选中匹配的范围。
- 「Open in editor」：用当前查询发一个 `DeploySearch`，交给上游的标签页。

| # | 内容 | 原因 |

| 9 | **文件内容变化**：结果是锚点，文件被编辑后片段不自动更新；标题行的 ↻ 重新搜索 | 和 VS Code 一样，不自动重搜 |

## 代码位置与挂钩

按 fork 的约定做成新 crate，**不改上游 `search` crate**：

```
crates/fork_search_panel/
  Cargo.toml          [lib] path = "src/fork_search_panel.rs"
  src/fork_search_panel.rs   面板、搜索、渲染、测试
```

- PR 用到的 `search` crate 内部函数在新 crate 里拿不到，处理方式：
  - `SearchOptions`、`ToggleRegex` 等 action：`search` 已经公开，直接用。
  - `split_glob_patterns`（`project_search.rs` 私有，约 30 行）：复制过来。
  - `search_bar::input_base_styles` / `render_text_input`（`pub(crate)`）：不用它们，输入框按 VS Code 样式自己画。
- **注册面板**：在 `fork_ext::init` 已有的 `observe_new::<Workspace>` 里异步 `load` 面板后调 `workspace.add_panel`，**不改 `zed.rs` 的 `initialize_panels`**。
- **快捷键**：在 `fork/keymaps/default-macos.json` 里，把 `Workspace` 和 `Editor` 两个上下文的 `cmd-shift-f` 绑到 `fork_search_panel::Deploy`。fork 键位排在官方默认之后（H8），会覆盖官方绑定。不用拦截 `pane::DeploySearch`，所以**不加新的上游挂钩**。
- 设置：`crates/settings_content/src/fork.rs`（H6，fork 自有文件）加 `ForkSearchPanelSettingsContent`。
- 改动的上游文件只有已有挂钩覆盖的 `Cargo.toml`（H1，加一个 member）和 `fork_ext` 的依赖，`HOOKS.md` 只需要在 H1 的说明里加上这个 crate。

### 不接管的入口

这些入口仍然打开上游的搜索标签页：

- 命令面板里的 `pane::DeploySearch`、vim 的 `g /`、`cmd-shift-h`（替换）。

项目面板右键的「Find in Folder…」（`project_panel::NewSearchInDirectory`）已接管：项目面板仍按所选文件夹、文件父目录与多根工作区解析目录，再发出内部转发动作 `search::NewSearchInDirectory`。fork 在 Workspace 的 capture 阶段接住转发动作并打开侧边栏，无需修改上游 `project_panel` 或 `search`。关闭搜索侧边栏设置时不截断动作，继续打开上游搜索标签页。

## 设置

```json
{
  "fork": {
    "search_panel": {
      "enabled": true,
      "dock": "left",
      "default_width": 300,
      "search_on_type": true
    }
  }
}
```

- `enabled`：默认 `true`。关掉后不注册面板；`fork_search_panel::Deploy` 发现没有面板时转发 `pane::DeploySearch`，所以 `cmd-shift-f` 回到上游标签页，不用改键位。
- `dock`：`left` / `right` / `bottom`，默认 `left`。在面板上右键改停靠位置时写回这里。
- `search_on_type`：默认 `true`，输入时防抖自动搜索；关掉后只有回车才搜。

## 替换补齐（2026-11-18）

- 查询框左侧箭头展开 / 收起 Replace 输入；收起后保留输入内容。在面板中按 `cmd-shift-h` 也可切换。
- Replace 右侧 `AB` 开关保留大小写：全大写、全小写、首字母大写分别转换；混合大小写和无大小写字符保持替换文本原样。支持 Unicode。
- 匹配行按钮替换单条；文件行按钮替换该文件全部命中；Replace 右侧按钮替换所有文件命中。文件内 / 全部替换先显示确认提示。
- 替换框内 `enter` 替换当前选中匹配（选中文件行时取该文件第一条）；`cmd-enter` 全部替换；`down` 转到结果列表。查询 / 过滤框内 `enter` 仍立即搜索，不会替换。
- 正则替换复用上游公开的 `SearchQuery::replacement_for`：捕获组、命名组、前后查找上下文及 `\n` / `\t` 转义均可用；空替换文本表示删除。
- 替换文本和保留大小写开关变化只更新 UI，不取消或重启搜索。修改搜索文本 / 选项仍使旧结果失效。
- 操作前重新检查当前命中、原文本、缓冲区版本、只读状态和输入是否变化；全部文件预检通过后才编辑，避免旧锚点误改或只改了一部分文件。搜索中或达到搜索上限时禁用替换，需等搜索完成或缩小范围。
- **不主动保存**：受影响文件以非预览标签页打开，保留未保存改动和撤销历史，焦点不离开面板。每个文件内的一次替换是独立撤销组，不与此前手工编辑合并。保存仍由用户操作；已有自动保存设置继续生效。
- 「Open in editor」仍只交接查询、搜索选项与过滤条件，不传递替换文本或保留大小写状态；上游 `search` crate 未修改。

键位上下文使用 `fork_search_input > Editor` 和 `fork_replace_input > Editor`，因为容器与 Editor 是父子节点，不是同一节点上的属性。

## 文件夹搜索入口补齐（2026-11-18）

- 文件树右键「Find in Folder…」及其现有快捷键打开搜索侧边栏，不新增搜索标签页。
- 自动展开文件过滤条件，包含范围设为所选目录；选中文件时使用父目录，多根工作区沿用项目面板传入的根目录前缀。覆盖旧包含范围并清空旧排除范围，避免此前的过滤条件屏蔽新目录。
- 当前编辑器有单行选区时用选区填入查询，否则保留侧边栏已有查询；查询输入框全选并聚焦，重新搜索。
- 运行时关闭侧边栏后恢复上游目录搜索；重新开启后再次接管。其他明确保留的编辑器搜索入口不受影响。
- 回归测试通过真实 `project_panel::NewSearchInDirectory` 动作验证目录、文件父目录、根目录、多根工作区、输入焦点、不新增搜索标签页，以及关闭 / 重新开启后的行为。

验证通过：21 项测试（18 项 GPUI、3 项纯函数），GPUI 测试执行 20 轮调度种子检查；`cargo check -p fork_search_panel -p fork_ext`、`./script/clippy -p fork_search_panel -p fork_ext` 与 `cargo build -p zed` 均通过。debug 二进制更新到同一缓存路径，仍须从对应源码工作区目录启动以加载开发资源。

## 命中词背景高亮（2026-11-18）

搜索结果片段的命中词由蓝色文字改为背景底色高亮，文字沿用正常文本颜色。底色使用当前主题的 `search.match_background`，与编辑器内搜索命中底色一致，不固定棕色；保留原有字号、行高、截断和 UTF-8 高亮范围。修改仅限 fork 搜索侧边栏，不改变其他列表的 `HighlightedLabel` 样式。

验证通过：22 项测试（19 项 GPUI、3 项纯函数），GPUI 测试执行 20 轮调度种子检查；check、`./script/clippy`、debug 构建、rustfmt 与 `git diff --check` 均通过。新增回归覆盖中文和英文命中范围、背景主题色与正常文本样式。桌面样式仍由用户启动新版二进制确认。
