# 3. Copy Anchor

> 本仓库是 zed-industries/zed 的个人 fork。整体设计见 `0.整体设计.md`。

## 目标

在 `fork_copy_anchor` 里实现 context-kit 的 Copy Anchor：复制选中代码时带上文件路径和行号。行为以 `context-kit/src/features/copy-anchor/README.md` 为准。

这是第一个真正的功能，同时用来验证阶段 1 的接入框架（动作、键位条件、状态栏、设置）。

## 输出格式

选中文件片段后按 `cmd-c`，剪贴板内容为：

````text
```/Users/zeke/workspace/my-app/src/main.ts:8-11
function greet(name: string) {
  const message = `Hello, ${name}`;
  return message;
}
```
````

## 要做的事

### 3.1 核心逻辑（纯函数，不依赖 gpui）

从 `core/contextText.ts` 和 `core/copyPreview.ts` 移植：

- 生成带 `路径:起始行-结束行` 的代码块，单行时为 `路径:行`，行号从 1 开始。
- 只移除选区首尾的空白行并同步调整行号，保留缩进、行尾空格和中间空行。
- 换行统一为 LF。
- 选区内含 Markdown 代码围栏时，外层围栏自动加长。
- 状态栏预览文本：缩短目录、去掉外层围栏、换行显示为字面的 `\n`、按字符数截断且不切断 Unicode 字符。

context-kit 的 `tests/unit/` 里对应的用例全部移植为 Rust 单元测试。

### 3.2 动作与键位

| 动作 | 默认键位 | 生效条件 |
|---|---|---|
| `copy_anchor::Copy` | `cmd-c` | 编辑器有焦点、有非空选区、功能已开启 |
| `copy_anchor::ToggleContextMode` | `ctrl-\ ctrl-\` | 编辑器有焦点、功能已开启 |

生效条件通过 `Addon::extend_key_context` 往编辑器键位上下文里加标记实现。功能关闭时标记不存在，`cmd-c` 回到官方的 `editor::Copy`。

### 3.3 复制行为

| 场景 | 剪贴板内容 |
|---|---|
| 上下文模式，选中文件片段 | 路径、行号和选中内容 |
| 上下文模式，完整选中整个文件 | 只有绝对路径 |
| 多选区 | 按文件内顺序分别输出代码块 |
| 未保存的新文件、没有磁盘路径的 buffer | 原生复制 |
| 多 buffer 视图（搜索结果、诊断面板等） | 原生复制 |
| 无选区 | 原生复制（键位条件已排除） |
| 普通模式 | 原生复制 |

「原生复制」指转发给 `editor::Copy`，不自己重新实现。

已保存文件里尚未保存的修改按当前编辑器内容复制。远程项目（SSH）使用远端的绝对路径。

### 3.4 模式切换

- 三个入口：键位、点击状态栏右侧标识、命令面板。
- 切换时把新模式写回用户设置的 `fork.copy_anchor.context_mode`。
- 切换后，剪贴板在上次通过本功能复制的「原文」和「带锚点文本」之间互换，不用重新按 `cmd-c`。
- 如果剪贴板已被别的复制操作替换，或还没通过本功能复制过，就按当前非空选区重新复制；没有选区则不动剪贴板。
- 两份文本只保存在内存里，关闭功能时清空。

### 3.5 状态栏

- 右侧：模式标识，上下文模式和普通模式各一个图标，可点击切换。
- 左侧：复制预览 `copied: …`，`preview_duration` 秒后消失，再次复制重新计时；`preview_duration` 为 0 时不显示。
- 功能关闭时两个状态栏项都隐藏。

### 3.6 设置

`fork.copy_anchor` 下四个字段：`enabled`、`context_mode`、`preview_max_length`（1–1000）、`preview_duration`（0–3600，支持小数）。修改后即时生效，不需要重启。

## 验收标准

| # | 标准 | 验证方法 |
|---|---|---|
| 1 | 移植的核心单元测试全部通过 | `cargo test -p fork_copy_anchor` |
| 2 | 3.3 表格里的每个场景行为正确 | gpui 测试（`TestAppContext`）逐条覆盖，断言剪贴板内容 |
| 3 | 选区首尾有空行时，行号与实际代码行一致 | 单元测试 + 手动粘贴核对 |
| 4 | 选中内容含 ``` 围栏时，粘贴到 Markdown 渲染器里不会被截断 | 单元测试 |
| 5 | 切换模式后剪贴板内容在两种形式间互换；剪贴板被外部覆盖后切换不会写回旧内容 | gpui 测试 |
| 6 | `enabled` 改为 `false` 后：`cmd-c` 是原生复制，状态栏项消失，切换键位不生效；改回 `true` 立即恢复 | 手动，不重启 |
| 7 | 用户在 `keymap.json` 里能把 `copy_anchor::Copy` 改绑到别的键，并恢复 `cmd-c` 为原生复制 | 手动 |
| 8 | Vim 模式开启时，`y` 等 Vim 复制不受影响 | 手动 |
| 9 | 菜单栏和右键菜单里的「复制」仍是原生复制 | 手动 |
| 10 | 本阶段没有新增上游挂钩 | `fork/check-hooks.sh` |

## 待确认事项

- `ctrl-\ ctrl-\` 在 Zed 默认键位里是否和已有绑定冲突，冲突的话换一个默认键并记录。
- Zed 状态栏是否适合显示 emoji。不适合就改用 Zed 自带图标。
- 自己写入剪贴板后，怎么判断「剪贴板已被外部覆盖」：读回剪贴板文本和内存里的两份做比较。

## 与 VS Code 版的差异

- 设置键从 `contextKit.copyAnchor.*` 变为 `fork.copy_anchor.*`。
- 模式始终写入用户设置，不区分工作区设置。
