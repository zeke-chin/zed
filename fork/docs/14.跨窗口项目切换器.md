# 14. 跨窗口项目切换器

> 本仓库是 zed-industries/zed 的个人 fork。整体设计见 `0.整体设计.md`。

## 目标

现在有两种切换项目的方式，各管一半，都不能搜索：

| 方式 | 范围 | 能否搜索 |
|---|---|---|
| Sidebar（`multi_workspace::ToggleWorkspaceSidebar`） | 只限当前窗口里的项目 | 不能 |
| macOS `` cmd-` `` | 只在窗口之间切换 | 不能 |
| `projects::OpenRecent` | 当前窗口的项目，加上最近打开的项目 | 能，但选中其他窗口里已打开的项目时，会在**当前窗口**里再开一份，不会跳到那个窗口 |

新增一个 picker：**把所有窗口里的所有项目列在一个搜索框里，选中后直接跳过去**。如果目标在别的窗口，就把那个窗口提到最前面，再在那个窗口里切到这个项目。

```
┌───────────────────────────────────────────────────────┐
│ Switch to project…                                    │
├───────────────────────────────────────────────────────┤
│   zed            ~/workspace/github_work/zed   当前   │  当前窗口当前项目，放第一行
│ ▸ context-kit    ~/workspace/github_work/context-kit  │  默认选中第二行（和 cmd-tab 一样）
│   api-server     ~/workspace/work/api-server   窗口 2 │
│   web            ~/workspace/work/web          窗口 2 │
│   infra          ssh: dev-box ~/infra          窗口 3 │  远程项目显示主机名
└───────────────────────────────────────────────────────┘
```

**范围**：

- 只列出**已经打开的**窗口里的项目，不列最近项目，那部分继续用 `projects::OpenRecent`。
- 不做关闭项目、移动项目到别的窗口这类操作，只负责切换。
- 不加设置项。

## 交互

- 新 action `window_switcher::Toggle`，在 `Workspace` 上注册，打开一个 modal picker。
- 默认键位 `ctrl-cmd-w`，放在 `fork/keymaps/default-macos.json` 的 `Workspace` 上下文里（见下面「快捷键」）。
- 输入框做模糊匹配，匹配的是项目名加路径（远程项目再加上主机名），和 `file_finder` 一样高亮命中的字符。
- 没有输入时，第一行是当前项目，默认选中第二行，这样「快捷键 → 回车」就能回到上一个用过的项目。有输入时默认选中匹配度最高的一行。
- `enter`：切过去并关掉 picker。`escape`：关掉 picker。

## 快捷键

按「w = window，p = project」重新分配。和 VS Code 一样，`ctrl-w` 是 Switch Window，`ctrl-r` 是 Open Recent：

| 键 | 现在 | 改成 |
|---|---|---|
| `ctrl-cmd-w` | `projects::OpenRecent`（个人 keymap） | `window_switcher::Toggle`：跨窗口切项目 |
| `ctrl-cmd-p` | `editor::AddSelectionAbove`（上游默认，`Editor` 上下文） | `projects::OpenRecent`：当前窗口的项目加最近项目 |

- `ctrl-cmd-w` 在上游默认 keymap 里是 `git::Worktree`（`Workspace` 上下文）。fork keymap 在上游默认之后加载，同一上下文下会覆盖它。`git::Worktree` 还能从命令面板打开。
- 个人 `~/.config/zed/keymap.json` 里的 `"ctrl-cmd-w": "projects::OpenRecent"` 优先级最高，会盖住 fork 的默认键位，所以要从那里删掉。这是个人配置，不在仓库里，需要手动改，具体改法见下面「个人 keymap」。
- `ctrl-cmd-p` 的上游绑定在 `Editor` 上下文里。上下文越深优先级越高，只绑在 `Workspace` 上的话，焦点在编辑器里时按下去执行的还是 `AddSelectionAbove`。所以个人 keymap 里要在 `Workspace` 和 `Editor` 两个上下文都绑一次（和现在 `cmd-g` 同时绑 `Pane` 与 `Workspace` 是一个道理）。`AddSelectionAbove` 还有 `cmd-alt-up` 可以用。
- `OpenRecent` 原有的 `alt-cmd-o` 和 `ctrl-r` 保持不变。

### fork 默认 keymap（`fork/keymaps/default-macos.json`，随代码提交）

追加一段：

```json
{
  "context": "Workspace",
  "bindings": {
    "ctrl-cmd-w": "window_switcher::Toggle"
  }
}
```

### 个人 keymap（`~/.config/zed/keymap.json`，手动修改）

第一个 `"context": "Workspace"` 段里，把

```json
      // 沿用 VS Code 习惯：搜索并切换项目，与 ctrl-r 相同
      "ctrl-cmd-w": "projects::OpenRecent",
```

改成

```json
      // w = window：ctrl-cmd-w 留给 fork 的跨窗口切换器（window_switcher::Toggle），这里不绑。
      // p = project：搜索并切换项目，与 ctrl-r 相同
      "ctrl-cmd-p": "projects::OpenRecent",
```

再追加一段 `Editor` 上下文，盖住上游 `Editor` 里的 `cmd-ctrl-p`（`editor::AddSelectionAbove`）：

```json
  {
    // 上游在 Editor 上下文把 cmd-ctrl-p 绑给 AddSelectionAbove，
    // 只绑 Workspace 时焦点在编辑器里会被它抢走，所以这里再绑一次。
    // AddSelectionAbove 仍可用 cmd-alt-up。
    "context": "Editor",
    "bindings": {
      "ctrl-cmd-p": "projects::OpenRecent",
    },
  },
```

个人 keymap 的这两处改动不依赖新功能，可以先改。改完、新功能合进 `fork` 之前，`ctrl-cmd-w` 执行的是上游默认的 `git::Worktree`。

## 列表内容

### 一行是什么

**一行对应一个窗口里的一个项目分组**，也就是 Sidebar 里的一个项目标题（`ProjectGroupKey`），不再细分到 worktree 或 agent 线程这一层。没有开 multi workspace 的窗口只有一个项目，也只占一行。

数据来源：

1. `cx.windows()` 里所有能 `downcast::<MultiWorkspace>()` 的窗口。
2. 每个窗口的 `MultiWorkspace::project_groups(cx)`，按 Sidebar 里的顺序排列。
3. 项目名用 `ProjectGroupKey::display_name`（和 Sidebar 标题一样）。路径取 `path_list()` 的第一个路径，显示成 `~/…` 的形式。有多个根目录的项目，名字本身已经是用逗号连起来的。
4. `host()` 不为空时是远程项目，路径前面加上 `ssh: <主机名>`。

Sidebar 里有些分组只是恢复出来的标题，背后还没有打开的 workspace（`project_groups` 里的 `workspaces` 是空的），它们也列出来，因为在 Sidebar 里也点得到。

### 排序

1. 窗口按前后层级排序：最前面的窗口排第一。用的是 `cx.window_stack()`，macOS 上它返回的就是从前到后的窗口顺序。
2. 同一个窗口里，当前激活的项目排第一，其他项目按 Sidebar 顺序。

`window_stack()` 返回 `None` 时（测试平台、Linux 部分环境），先放当前活动窗口，其余窗口按 `cx.windows()` 的顺序排。

这样排出来的第二行，要么是当前窗口里的另一个项目，要么是上一个用过的窗口里的当前项目，基本就是「上一个」。项目级别的最近使用时间（`held.activated_at`）是 `MultiWorkspace` 的私有字段，而且只在单个窗口内部有意义，所以不用它来做跨窗口的排序。

### 右侧标记

- 当前窗口的当前项目标「当前」。
- 其他窗口的项目标「窗口 N」，N 是上面排序后窗口的序号（当前窗口是 1）。序号只用来区分哪几个项目在同一个窗口里，不和系统的窗口编号对应。
- 当前窗口里的其他项目不加标记。

## 切换的行为

选中一行后：

1. 目标窗口不是当前窗口时，调用 `window.activate_window()` 把它提到最前面并获得焦点。
2. 在目标窗口里切到这个项目，逻辑和 `recent_projects` 里 `ProjectPickerEntry::ProjectGroup` 的 `confirm` 一样：
   - `last_active_workspace_for_group(&key)` 能找到 workspace 时，调用 `MultiWorkspace::activate` 激活它。
   - 找不到时（只有标题的分组），调用 `find_or_create_workspace` 打开它，远程项目通过 `connect_with_modal` 连接。
3. 选中的就是当前窗口的当前项目时，只关掉 picker，不做别的。

窗口在 picker 打开后被关掉的，`handle.update` 会返回错误，用 `log_err()` 记录下来，然后关掉 picker。

## 代码放在哪

新建 crate `crates/fork_window_switcher`，在 `fork_ext::init` 里调用 `fork_window_switcher::init(cx)`。它只调用 `workspace`、`picker`、`project`、`remote_connection`、`gpui`、`ui` 的公开接口，**不改上游文件**：

- 用到的 `MultiWorkspace::project_groups`、`last_active_workspace_for_group`、`activate`、`find_or_create_workspace` 都是 `pub` 的。
- Picker 的写法参考 `tab_switcher`：一个 `WindowSwitcher` modal 包着 `Picker<WindowSwitcherDelegate>`，在 `Workspace` 上用 `register_action` 注册。
- `connect_with_modal` 是 `remote_connection` crate 里的 `pub fn`，可以直接用。

挂钩只有新增 crate 必须要改的两处，都已经在现有清单的范围里：

- 根目录 `Cargo.toml` 的 `members` 和 `[workspace.dependencies]` 各加一行（H1）。
- `crates/fork_ext/Cargo.toml` 加依赖，`fork_ext.rs` 加一行 `init` 调用，这些都是 fork 自己的文件，不算挂钩。

## 测试

在 `fork_window_switcher` 里写 gpui 测试，用 `FakeFs` 建几个项目目录：

- 两个窗口，窗口 1 里有项目 A、B（A 是当前），窗口 2 里有项目 C。打开 picker：顺序是 A、B、C，默认选中 B，标记分别是「当前」、空、「窗口 2」。
- 输入 `c` 只剩 C；回车后窗口 2 变成活动窗口，它当前的项目是 C。
- 在窗口 1 里选 B：窗口不变，`MultiWorkspace::workspace()` 变成 B。
- 选当前项目：什么都不变，picker 关掉。
- 有一个只剩标题、还没有打开 workspace 的分组时，选中它会打开对应的 workspace。

测试平台的 `window_stack()` 返回 `None`，排序测试走的是上面写的回退逻辑。macOS 上真实的前后顺序靠手动验证。

手动验证：

1. 开三个窗口，其中一个窗口的 Sidebar 里放两个项目。
2. 按快捷键加回车，能在最近两个项目之间来回切。
3. 搜索另一个窗口里的项目，回车后那个窗口到最前面，而且显示的就是这个项目。
4. 远程项目能列出来，标出主机名。
