# 11. 侧边栏项目默认折叠

> 本仓库是 zed-industries/zed 的个人 fork。整体设计见 `0.整体设计.md`。

## 目标

左侧 Threads 侧边栏按项目分组，每个项目标题下列出它的 agent 线程。我不用 agent 线程，只把这个侧边栏当作工作区（项目）切换器用。上游的两个默认行为对这种用法不顺手：

1. **新项目默认展开**：每加入一个项目，标题下面就多出一行「No threads yet」，列表被撑开。
2. **单击标题是展开/折叠，⌘-单击才是切到该项目**：最常用的操作要多按一个键。

改成：

| 操作 | 上游 | fork |
|---|---|---|
| 新加入的项目分组 | 展开 | **折叠** |
| 单击项目标题 | 展开/折叠 | **切到该项目**（上游 ⌘-单击的行为） |
| ⌘-单击项目标题 | 切到该项目 | **展开/折叠**（上游单击的行为） |

切到项目的具体行为沿用上游 `activate_or_open_workspace_for_group`：该项目已经打开就激活上次用的那个工作区，没打开就打开它；已经是当前项目时什么都不做。

不加设置项，直接改默认行为。

## 改动

### 默认折叠（挂钩 H17）

`crates/workspace/src/multi_workspace.rs` 的 `ensure_project_group_state` 是项目分组状态唯一的创建入口，新建 `ProjectGroupState` 时上游写死 `expanded: true`。

改成读 `MultiWorkspace` 上新加的字段 `fork_new_groups_expanded`：`new` 里是 `false`（真实启动走这里），上游测试用的构造函数 `test_new` 里是 `true`。上游 `sidebar_tests.rs` 有 80 多处断言默认展开，这样做上游测试不用改；fork 测试用 `fork_set_new_groups_expanded(false)` 打开新行为。

- 只影响**新**出现的分组。已经存进数据库的分组保留各自的展开状态，不做迁移；需要的话，焦点在侧边栏时执行 `editor: fold all`（侧边栏的 `fold_all`）一次收起。注意上游 `fold_all` 改完状态后没有调 `serialize`，要等下一次别的操作触发保存才会落盘；逐个 ⌘-单击收起则会立即保存。
- 上游在这些地方会主动展开分组，保持不变：在分组里新建线程/终端（`new_thread_in_group`、`new_terminal_thread`）、键盘在项目间跳转、右箭头 `SelectChild`。这些都是明确要看线程的操作。
- 有搜索词时上游本来就忽略折叠状态、照常列出匹配的线程，不受影响。

### 单击与 ⌘-单击对调（挂钩 H18）

`crates/sidebar/src/sidebar.rs`：

- `render_project_header` 的 `on_click`：把 `event.modifiers().secondary(cx)` 两个分支对调。不带修饰键 → `activate_or_open_workspace_for_group`；带 ⌘ 且没有搜索词 → `toggle_collapse`。
- 标题右键 / `…` 菜单里「Focus Project」「Focus Last Project」右侧的快捷提示原来是「⌘-click」，改成「click」，否则提示和实际行为对不上。
- **键盘 Enter**（`confirm` 落在项目标题上）：上游是展开/折叠。改成和单击一致，切到该项目；展开/折叠仍可用左右箭头（`SelectParent` / `SelectChild`）。

改动都很小，直接在上游文件里加 `// FORK:` 注释，不另建 crate。

## 测试

- 「新分组默认展开」由 `test_new` 保留，上游测试不受影响。Enter 的行为改了，上游 `test_keyboard_confirm_on_project_header_toggles_collapse` 按新行为改写（挂钩 H19）。
- 新增 fork 测试，放在 `sidebar_tests.rs` 末尾单独一段：
  - 新加入的项目分组是折叠的，不出现「No threads yet」行。
  - 单击非当前项目的标题会激活该工作区，折叠状态不变。
  - ⌘-单击标题切换展开/折叠，不切换工作区。
  - Enter 落在标题上时切到该项目。
- 手动验证：打开两个项目，单击来回切换；⌘-单击展开看到「No threads yet」，再 ⌘-单击收起。
