# 12. Blame 悬浮卡 GitLens 样式

> 本仓库是 zed-industries/zed 的个人 fork。整体设计见 `0.整体设计.md`。

## 目标

鼠标停在行尾 inline blame 上（或执行 `editor: blame hover`）时弹出的悬浮卡，改成 VS Code 里 GitLens 的样子。最重要的一块是**这一行在该 commit 里改了什么**（下图的 diff 区）：

```
┌──────────────────────────────────────────────────────────────┐
│ [头像] heng.pan  🕓 3 weeks ago (October 21st, 2026 11:11 AM) │ 头部：作者用链接色，括号里的绝对时间用斜体
│                                                              │
│ feat: migrate attachment uploads to Resource APIs            │ commit message（Markdown）
│                                                              │
│ ⊸ a49ae7c  ⧉                                                 │ sha（链接色）＋复制按钮，没有别的按钮
│                                                              │
│ - | POST | `/aisales/agent/api/v1/upload/pre` | 获取 COS 直传 │ diff 区：buffer 字体，− 行红色，+ 行绿色
│   凭证 |                                                     │ 太长的行自动换行，不截断
│ + | GET | `/aisales/agent/api/v1/upload/config` | 查询附件有 │
│   效大小、格式与解析策略 |                                   ▐ 整张卡有最大高度，超出时上下滚动
│                                                              │
│ Changes  ⊸ffaeea2 ↔ ⊸a49ae7c  [±]                            │ 父 commit ↔ 本 commit，最后是打开改动的图标按钮
└──────────────────────────────────────────────────────────────┘
```

对照的是 GitLens 实际的表现：diff 行很长时自动换行，内容超出最大高度时整张卡（包括头部、message、diff 区、Changes 行）一起上下滚动，右侧出现滚动条。

要求结构和信息与 GitLens 一致。字体、图标、圆角阴影沿用 Zed 主题，不追求像素级一致。

**范围**：

- 只支持本地仓库。远程项目（SSH、collab）不显示 diff 区，其余部分照常显示。
- GitLens 操作栏里的其他按钮（打开改动、搜索、Explain、设置、`⋯`）都不做，只留 sha 和复制。

## 设置

```json
{
  "fork": {
    "blame_popover": { "style": "gitlens" }
  }
}
```

- `fork.blame_popover.style`：`"zed"`（默认，上游样式）或 `"gitlens"`。改了立即生效：悬浮卡每次显示都重新渲染，不用重启。
- 只能在 `settings.json` 里改，不加到设置界面（Settings UI）。

## 各区块

### 头部

- 头像：沿用上游的 `CommitAvatar`（有 GitHub 远程时取 GitHub 头像，否则用默认图标）。
- 作者名：用 `text_accent` 色，不可点击。不显示邮箱（GitLens 不显示）。
- 时钟图标 `IconName::Clock`，后面是相对时间加括号里的绝对时间，绝对时间用斜体。
  - 相对时间沿用上游的 `blame_entry_timestamp(…, Relative)`。
  - 绝对时间按 GitLens 的默认格式 `MMMM Do, YYYY h:mm A` 自己格式化（`October 21st, 2026 11:11 AM`），用本地时区。时间来源和相对时间一样，保证两者一致。
  - 序数后缀：11、12、13 用 `th`，其余尾数是 1、2、3 的分别用 `st`、`nd`、`rd`，其他都用 `th`。

### commit message

直接用上游已解析好的 Markdown（`ParsedCommitMessage` 和 `markdown` 实体）。message 不再单独限高滚动，改由整张卡滚动（见「尺寸和滚动」）。不加分隔线。浅克隆边界提示（`shallow_boundary_notice`）照常显示在 message 上方。

### sha 和复制

- `⊸ a49ae7c`：`IconName::GitCommit` 加短 sha，链接色。点击打开 CommitView 并定位到本文件，和上游 sha 按钮的行为一样。
- 复制按钮：上游的 `CopyButton`，提示文字 `Copy SHA`，复制完整 sha。
- 上游底部的 PR 按钮、tag chips 不再显示（GitLens 截图里没有）。

### diff 区（重点）

显示悬浮的这一行在该 commit 里的改动。

**取数据**（只限本地仓库）：

1. 求出这一行在该 commit 版本文件里的行号 `L`（见下文「行号」）。
2. 读出该 commit 版本的文件内容 `sha:filename`，以及父版本内容 `previous_sha:previous_filename`（来自 `BlameEntry::previous_sha_and_filename()`，文件改名时旧路径不同）。用的是 git 后端已有的 `load_revisions`，一次读两个，上游没有对外公开，所以加挂钩 H22。
3. 用 `language::line_diff(old, new)` 做行级 diff，找出新版本行范围包含 `L` 的那个 hunk。

**显示哪些行**：

| 情况 | − 行 | + 行 |
|---|---|---|
| 父版本不存在（文件在该 commit 新建，或浅克隆边界） | 不显示 | 当前行 |
| hunk 只有新增（旧范围为空） | 不显示 | 当前行 |
| hunk 新旧行数相同（截图的情况） | 旧版本里对应位置的那一行 | 当前行 |
| hunk 新旧行数不同 | 旧范围的全部行 | 当前行 |
| 找不到包含 `L` 的 hunk（理论上不会出现，blame 说这行是这个 commit 改的） | 整个 diff 区不显示 | |

**渲染**：

- buffer 字体，每行前加 `- ` 或 `+ `。整行文字分别用主题的 `version_control_deleted` 和 `version_control_added` 着色，不做语法高亮，也没有背景色。
- 超出悬浮卡宽度的行自动换行，不截断；换行后的续行和首行一样着色。tab 换成 4 个空格，缩进保持原样。

**异步和缓存**：

- 悬浮卡的渲染是同步的，diff 要异步算。fork 模块里放一个全局缓存，键是 `(仓库, sha, filename)`，值是 `Loading`、`Ready(hunks)` 或 `Unavailable`。`hunks` 只保存各 hunk 的行范围和需要显示的行文本，不保存整个文件。
- 渲染时缓存里没有就设成 `Loading` 并启动后台任务，算完写回缓存，再刷新窗口。`Loading` 期间不显示 diff 区，也不放占位；本地读取通常在悬浮卡的显示延迟（`hover_popover_delay`）内就完成了。
- commit 内容不会变，缓存不用失效，只按最近使用淘汰，最多保留 64 个。
- 以下情况记为 `Unavailable`，不显示 diff 区：远程仓库；任一版本读不到或是二进制文件；任一版本超过 2 MB；读取出错（用 `log_err` 记日志）。

### Changes 行

- 文字 `Changes`，后面是父 commit 的短 sha，`↔`，本 commit 的短 sha，都是 commit 图标加链接色。
  - 点父 commit sha：打开父 commit 的 CommitView。
  - 点本 commit sha：打开本 commit 的 CommitView 并定位到本文件。
- 最后一个图标按钮（`IconName::FileDiff`，提示 `Open Changes`）：行为和点本 commit sha 一样。GitLens 这里打开的是「本文件与上一版本的对比」，Zed 里最接近的就是 CommitView 定位到本文件。
- 没有父 commit 时只显示 `Changes  ⊸a49ae7c  [±]`。

### 未提交的行

sha 全为 0 的行（Uncommitted changes）：头部和 message 照常显示，不显示 sha 行、diff 区和 Changes 行。

### 尺寸和滚动

- 宽度：上游固定 `30rem`。GitLens 样式改成随内容变宽，最大 `40rem`。commit message 和 diff 行超宽时都自动换行。
- 高度：整张卡的内容放进一个可上下滚动的容器，最大高度沿用上游给 message 的上限（`window.line_height() * 12 + ui_font_size / 0.4`）。内容没超出时卡片按内容高度显示，没有滚动条。
- 滚动用上游已经传进来的 `scroll_handle`，原来挂在 message 上，现在挂在整张卡的容器上。悬浮卡已有的 `on_mouse_move` / `on_mouse_down` 拦截保留，滚轮事件不会传到下面的编辑器。

## 行号

blame 条目覆盖连续的若干行，上游传给悬浮卡的是整个条目，`original_line_number` 是条目**第一行**在该 commit 版本里的行号，不是悬浮那一行的。悬浮卡总是对应光标所在行（inline blame 只画在光标行上），所以：

- 在 `GitBlame` 上加 `fork_row_offset_in_entry(buffer_id, row)`（H21）：用条目 sum tree 的游标求出 `row` 相对所在条目片段起点的偏移。
- `EditorElement::layout_blame_popover` 已经拿到了光标的 buffer 行。在它取到条目之后（H20），把条目收窄到这一行：`original_line_number += offset`，`range` 改成这一行。上游悬浮卡只用 sha、作者、时间、filename 这些字段，收窄对它没有影响，所以不区分样式，一律收窄。

**已知限制**：在一个 blame 条目中间插入或删除行、还没保存时，条目会被拆成几段，偏移在这期间可能不准。上游在编辑后 2 秒会用缓冲区内容重新 blame（`REGENERATE_ON_EDIT_DEBOUNCE_INTERVAL`），之后就恢复正确。不为这 2 秒另做处理。

完成时同步更新 `fork/HOOKS.md`（清单和同步上游时的处理方式）和 `fork/check-hooks.sh`。

## 没做的

- 远程项目的 diff 区：要加 proto 消息，工作量多一截，先不做。
- GitLens 操作栏的其他按钮（打开改动、搜索、Explain、设置、`⋯`）。
- 作者名点击（GitLens 是 `mailto:` 链接）。
- diff 行的语法高亮（GitLens 也没有）。
- 不追求像素级一致：字体、图标集、悬浮卡圆角阴影都沿用 Zed。
