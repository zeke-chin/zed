# 6. JSON Explorer

> 本仓库是 zed-industries/zed 的个人 fork。整体设计见 `0.整体设计.md`。

## 目标

在 `fork_json_explorer` 里实现 context-kit 的 JSON Explorer：粘贴时识别并格式化 JSON、JSON 与 JSON 字符串互转、修复 Python repr 和字符串内换行、字符串值的 Hover 预览、把嵌套值解析到右侧分栏。行为以 `context-kit/src/features/json-explorer/README.md` 为准。

前置：阶段 1 完成。与 Windsurf 线互不依赖。

## 模块划分

```
fork_json_explorer/src/
  fork_json_explorer.rs   # init、attach_editor
  core.rs                 # JSON 判断与转换、Markdown 识别
  python_repr.rs          # Python 字面量解析
  line_break_repair.rs    # 字符串内换行修复
  paste_detection.rs      # 粘贴识别
  commands.rs             # 转换动作
  hover.rs                # SemanticsProvider 装饰器、悬浮窗 Markdown
  nested.rs               # ParseNestedValue、悬浮窗链接处理
  pending_opens.rs        # 悬浮窗链接令牌缓存
```

## 要做的事

### 6.1 核心算法（纯函数）

从 `core/` 移植，约 900 行 TypeScript：

| 模块 | 内容 |
|---|---|
| JSON 工具 | 判断文本是合法 JSON、JSON 字符串还是其他；格式化；JSON 与 JSON 字符串互转；按光标偏移找到所在的字符串值及其键路径 |
| Python repr | 解析 `dict` / `list` / `tuple` / 三种引号的 `str` / `int` / `float` / `True` / `False` / `None`，转成 JSON |
| 换行修复 | 把字符串字面量内部的真实换行转义，结构性换行不动 |
| Markdown 识别 | 根据标题、列表、围栏、链接、表格等信号判断字符串是不是 Markdown |

约束：

- ~~JSON 解析用 `serde_json`~~ 实现时改为自写的 `core::json_value::JsonValue`：数字以原始文本保存，解析和输出都不经过 f64，键顺序严格按原文。`serde_json` 要保留数字原文必须开 `arbitrary_precision`，那是全局特性，会影响整个 Zed，所以不用。
- 大整数和高精度小数不能在转换中丢精度，按原始数字文本保留。TS 版实际做不到（`JSON.parse` 再 `JSON.stringify` 会把 `1.0` 改成 `1`、大数丢精度），这一点 Rust 版有意和 TS 版不同。
- 已知和 TS 版的其他差异：整数形状的键不会被提前（JS 对象会）；孤立代理项 `\ud800` 解析后变成 U+FFFD；嵌套深度超过 512 返回 `None`（防止栈溢出）。
- 验收 2（与 TS 版逐字节一致）目前只用 TS 测试里的期望输出做了对照，还没有在同一批输入上实际跑 TS 版比对，留到 J2/J3 之后补一个对照脚本。
- Python repr 不支持的输入（函数调用、对象引用、`bytes`、`set`、非字符串键）必须原样保留，不报错、不误转。
- JSONC（带注释和尾逗号）的处理方式与 TypeScript 版一致。

context-kit 的 `tests/unit/` 里对应用例全部移植。

### 6.2 粘贴识别

在 Plain Text buffer 里，一次编辑把整个内容替换掉（空文件粘贴，或全选后粘贴）时检测内容：

| 内容 | 默认行为 | 对应的自动转换设置为 `true` 时 |
|---|---|---|
| 合法 JSON 或 JSON 字符串 | 切换语言为 JSON 并格式化 | 不适用 |
| Python repr | 不改动，显示可转换提示 | 自动转成 JSON |
| 含字符串内换行的 JSON | 不改动，显示可转换提示 | 自动修复并转成 JSON |

实现方式：订阅 buffer 的编辑事件，判断是否为整体替换。检测在后台线程做，内容过大时（上限待定）跳过。

自动格式化作为一次独立的编辑事务，一次撤销回到粘贴后的原始文本，再撤销一次回到粘贴前。

「可转换提示」：Zed 没有可用的 CodeLens 通道，改为在状态栏显示一个可点击的提示项，同时 `cmd-;` 可直接触发。

实现记录（J2）：

- 判断「整体替换」：`BufferEvent::Edited` 不带编辑范围，改为在 attach 时对 buffer 调 `subscribe()`，每次 `Edited` 取 `Patch`，要求恰好一处编辑、旧范围 `0..上次长度`、新范围 `0..当前长度`，且 `source == User`。粘贴和「全选后输入」在 buffer 层无法区分，所以全选后打字替换也会走检测（只有首个非空白字符是 `{` `[` `"` 才继续）。
- 排除文件重载：`Reloaded` 事件递增计数，后台检测完成时若计数变化或 buffer 不是 dirty 就放弃；版本变化同样放弃。
- 检测与转换的字节上限定为 64 MiB，超过则跳过。`format_json_or_json_string` 在后台线程执行，主线程只做版本校验和一次替换。
- 转换是单独事务：转换前先 `finalize_last_transaction`，避免与粘贴事务按时间分组合并，转换后再 finalize 一次。语言切换不属于撤销历史，所以撤销后文本回到原始粘贴内容，但语言保持 JSON。
- 转换后光标移到文档末尾（与 VS Code 版一致）。
- 「可转换提示」：状态栏左侧一个按钮，文字为 `Convert Python repr to JSON` 或 `Repair line breaks and convert to JSON`，点击等同 `cmd-;`。提示只在粘贴检测后产生，记录 buffer 版本，buffer 一有编辑即失效。
- `cmd-;` 在 Plain Text 里不依赖提示：按下时重新检测当前内容，是 Python repr 或换行 JSON 就转换。这是对「有可转换提示时」的放宽，目的是打开的已有文件也能转换；合法 JSON 不转换（它在粘贴时已自动处理）。
- 键位上下文：`json_explorer_enabled`（功能开启）；`json_explorer_convertible`（开启且 JSON / JSONC / Plain Text）。`cmd-;` 绑在 `Editor && json_explorer_enabled && json_explorer_convertible`。Zed 默认键位里 `cmd-;` 是 `editor::ToggleLineNumbers`，fork 键位后加载所以覆盖了它，功能关闭或其他语言时仍是原行为。
- 只处理单 buffer 编辑器；多 buffer 编辑器（搜索结果等）不挂载。

### 6.3 转换动作

`json_explorer::ToggleCurrentDocument`，默认 `cmd-;`：

| 当前文档 | 行为 |
|---|---|
| JSON / JSONC | 在格式化 JSON 和 JSON 字符串之间切换 |
| Plain Text，且有可转换提示 | 执行对应转换，语言切到 JSON |
| 其他 | 不生效（键位条件排除） |

并发保护：一次转换完成前，同一 buffer 的下一次触发被忽略。

### 6.4 Hover 预览

用装饰器包住编辑器原有的 `SemanticsProvider`：`hover` 方法先取原 provider 的结果，再在 JSON / JSONC 文件里、光标位于字符串值上时追加一个预览块；其余 12 个方法原样转发。

| 字符串内容 | 预览 |
|---|---|
| 嵌套 JSON | 格式化后的 JSON 代码块 |
| Python dict 字符串 | 转成 JSON 后的代码块，标题注明来自 Python dict |
| Markdown | 按 Markdown 渲染 |
| 纯文本 | 等宽代码块，转义字符按真实换行和制表显示 |

预览超过 2000 字符时截断并标明。

悬浮窗的布局与 VS Code 版一致：

```
String value  description            ← 类型标题 + 键路径
▸ Open value in side panel           ← 可点击链接
<预览内容>
▸ Open value in side panel           ← 可点击链接（内容较长时方便点击）
```

链接文字随类型变化（`Open parsed JSON in side panel` 等）。链接地址是 fork 的自定义协议，形如 `zed-fork://json-explorer/open?token=<短令牌>`：

- 令牌对应内存里缓存的一条记录（buffer、字符串值的位置、buffer 版本），不把值本身放进链接。
- 点击经挂钩 H7 交给 `fork_json_explorer`，执行与 `ParseNestedValue` 相同的逻辑。
- buffer 在悬浮窗显示后被修改、令牌对应的版本已过期时，点击不执行并提示重新悬停。
- 令牌缓存有数量上限，随 buffer 关闭清理。

本阶段新增上游挂钩 H7（`crates/editor/src/hover_popover.rs`，约 10 行），设计见 `0.整体设计.md` 第 5.3 节。同一个提交里更新 `fork/HOOKS.md`。

实现记录（J3）：

- 代码在 `hover.rs`（装饰器与悬浮窗 Markdown）、`nested.rs`（`ParseNestedValue`、链接处理、开新文档）、`pending_opens.rs`（令牌缓存），gpui 测试在 `hover_tests.rs`。
- 装饰器在 `attach_editor` 里包住编辑器已有的 provider；上游只有 `Editor::new` 给 `semantics_provider` 赋值，`observe_new` 回调早于任何 Hover，不会被覆盖。编辑器没有 provider（无 project）时不包。
- 预览作为单独一个 `project::Hover` 追加在原结果之后，悬浮窗里是独立的一块，有自己的 `combine_hover_blocks` 预算（100 KB），不会挤掉 LSP 的 schema 说明，也不会被它截掉。Hover 范围是整个字符串字面量。
- 非 JSON / JSONC 文件、`enabled` 为 `false` 时直接返回原 provider 的任务，没有额外开销。JSON 文件里全文解析放在后台线程，与 LSP 请求并行。
- 令牌：Hover 时同步分配一个递增整数，后台算出命中后把（编辑器、buffer 弱引用、buffer 版本、值的偏移）存进全局缓存。上限 200 条，先进先出；每次存入时顺带清掉 buffer 已释放的条目。读取不消费，同一链接可点多次。
- 点击时 `buffer.version().changed_since(缓存的版本)` 为真就不打开，弹出提示「The document changed after this hover was shown. Hover the value again to open it.」。版本未变时按缓存的偏移重新从 buffer 读值，走与 `ParseNestedValue` 相同的函数。
- 预览截断按 Unicode 字符计数（TS 版按 UTF-16 码元），只影响含代理对字符时的截断位置。
- 格式化后的 JSON 用制表符缩进，与核心 `to_pretty_string`（与 TS 版一致）相同。

### 6.5 解析嵌套值

`json_explorer::ParseNestedValue`：光标在 JSON 字符串值上时，在右侧分栏新开一个未保存文档，内容是该值解析后的结果，按类型设置语言（JSON / Markdown / Plain Text）。

- 新文档标题带键路径，例如 `Parsed-data.json_str.json`。
- 新文档本身也是 JSON 或 Markdown，可以继续对它执行同一动作，支持任意深度嵌套。
- 多次执行在右侧同一分栏增加标签页。
- 默认键位待定，命令面板里可用。

实现记录（J3）：

- 未绑定默认键位，`fork/keymaps/default-macos.json` 没有改动；入口是命令面板和悬浮窗链接。用户自己绑定时建议上下文写 `Editor && json_explorer_enabled`（标记由 J2 提供）。
- 只在 JSON / JSONC buffer 里、光标在字符串值上（含两侧引号）时生效，否则什么也不做；`enabled` 为 `false` 时不生效。
- 新文档用 `Project::create_buffer` 创建（远程项目也可用），写入内容后丢掉这次编辑的撤销记录，撤销不会把文档清空。标题用 `MultiBuffer::with_title` 设置，例如 `Parsed-data.json_str.json`，同名文档不加序号。
- 目标分栏是源编辑器所在分栏右侧的分栏（`Workspace::adjacent_pane_of`），没有就向右拆分。所以从原文件多次执行都进同一个右侧分栏；在右侧新文档里继续解析会再往右开一栏，与 VS Code 的 `ViewColumn.Beside` 一致。
- 语言：嵌套 JSON 和 Python dict 为 JSON，Markdown 为 Markdown，纯文本为 Plain Text。

### 6.6 设置

`fork.json_explorer` 下三个字段：`enabled`、`python_repr_auto_convert`、`line_break_repair_auto_convert`。修改后即时生效。

## 与 VS Code 版的差异

| VS Code 版 | fork 版 |
|---|---|
| 文档顶部 CodeLens 按钮「Convert …」 | 状态栏提示项 + `cmd-;` |
| 字符串值上方 CodeLens「Parse JSON」 | 没有行内按钮，用悬浮窗链接或动作 `json_explorer::ParseNestedValue` |
| Hover 里的「Open in side panel」链接 | 相同，通过挂钩 H7 实现 |
| 设置键 `contextKit.jsonExplorer.*` | `fork.json_explorer.*` |

如果以后确实需要行内按钮，再评估给 `editor` 加一个 code action provider 的注册接口（会成为新的挂钩）。
