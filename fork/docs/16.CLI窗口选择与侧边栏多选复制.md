## 一、`zed <目录>` 时在终端里选目标窗口

### 目标

现在 `zed .` 按 `cli_default_open_behavior` 设置执行固定行为：要么总是新开窗口，要么总是加到当前窗口。我想每次在终端里当场选：

```
$ zed .
? Open aisales-cli-common-server in
❯ New window
  aisales-cli-common-server   (+5: aisales-doc, aisales-skills, …)
  zed                         (+1: context-kit)
```

- 第一项固定是「New window」，默认选中，所以直接回车就和 `zed -n` 一样。
- 后面每个已打开的 Zed 窗口占一行：显示窗口当前项目的名字；窗口里还有其他项目时，括号里写上数量和前几个名字。
- 上下键选，回车确认；`esc` / `q` 取消，什么都不打开，退出码 130。
- 选中某个窗口：把这个目录作为新项目加到该窗口的侧边栏，把窗口提到最前面并切到这个项目，和 `zed -e` 的效果一样，只是目标窗口由你指定，不再固定是最前面的窗口。

### 什么时候弹出选择

下面几个条件**全部满足**时才弹，否则保持上游行为：

1. 没有传打开方式参数（`-n`、`-e`、`-a`、`-r`、`--classic`）。传了就照参数执行，这几个参数可以当作跳过选择的快捷方式。
2. CLI 的 stdin 是终端。脚本、管道、`open -a` 之类的非交互调用不弹，照 `cli_default_open_behavior` 执行。
3. 至少有一个能加项目的 Zed 窗口（`MultiWorkspace` 窗口，且 `multi_workspace_enabled`）。一个窗口都没有时直接新开，没什么可选的。
4. 参数里至少有一个目录。只打开文件时沿用上游逻辑（文件属于某个已打开项目就跳到那个项目，否则放进当前窗口）。
5. 要打开的路径还没有被任何已打开的项目包含。已经包含时上游会直接跳到那个项目，这时候再问没有意义。

这个选择**替代**上游第一次运行时弹出的「设置默认打开方式」提示（`resolve_open_behavior` → `PromptOpenBehavior`）：满足上面条件时只弹 fork 的这个，不会再弹上游那个，也不写设置。上游的设置项仍然决定非交互调用的行为。

不加新的设置项。

### 窗口列表

在 Zed 进程里收集，发给 CLI：

- 来源：`cx.windows()` 里能 `downcast::<MultiWorkspace>()` 且 `multi_workspace_enabled` 的窗口。
- 顺序：按 `cx.window_stack()` 从前到后排，最前面的窗口排第一；`window_stack()` 返回 `None` 时按 `cx.windows()` 的顺序。这和 14 号文档里跨窗口切换器的排序规则一致，可以复用那边的写法，但不依赖 `fork_window_switcher` crate。
- 每一行显示的内容：
  - 主名字：窗口当前 workspace 的 `project_group_key(cx).display_name`，和侧边栏标题一样。
  - 括号：窗口里其他项目分组的数量和名字（按侧边栏顺序），最多列 3 个，超出部分用 `…`。只有一个项目时不显示括号。
  - 远程项目在名字前加 `ssh: <主机>`（WSL、Docker 也用各自的前缀，规则和 14 号文档相同）。
- 每一行带上窗口 id（`AnyWindowHandle::window_id().as_u64()`），CLI 选好后原样发回去。

### 协议改动（挂钩，改 `crates/cli/src/cli.rs`）

新增两条消息：

```rust
// Zed → CLI
CliResponse::PromptOpenTarget {
    target_name: String,           // 提示里显示的名字，取第一个目录的文件名
    windows: Vec<CliWindowEntry>,  // 已排好序
}

pub struct CliWindowEntry {
    pub window_id: u64,
    pub title: String,             // 主名字
    pub other_projects: Vec<String>,
}

// CLI → Zed
CliRequest::SetOpenTarget { target: CliOpenTarget }

pub enum CliOpenTarget {
    NewWindow,
    Window(u64),
    Cancel,
}
```

CLI 和 Zed 一起打包，版本总是一致，不考虑新旧版本混用的情况。

### CLI 端（挂钩，改 `crates/cli/src/main.rs`）

- 响应循环里处理 `CliResponse::PromptOpenTarget`：用已有依赖 `dialoguer::Select`（`.interact_opt()`）显示列表，把结果转成 `CliOpenTarget` 发回去。
- 「stdin 是不是终端」只有 CLI 知道，所以 CLI 在 `CliRequest::Open` 里多带一个字段 `interactive: bool`（`#[serde(default)]`），Zed 端只在它为 `true` 时才发提示。万一弹出时出错（`interact_opt` 返回 `Err`），CLI 发 `NewWindow`，不发 `Cancel`，避免 `zed .` 什么都不做。
- `esc` / `q` 返回 `None`，发 `Cancel`，CLI 收到 Zed 的 `Exit` 后以 130 退出。
- `Ctrl-C` 会直接结束 CLI 进程，Zed 端的 `requests.next()` 拿到 `None`，按取消处理。

### Zed 端（挂钩，改 `crates/zed/src/zed/open_listener.rs`）

在 `handle_cli_connection` 处理 `CliRequest::Open` 的地方、调用上游 `resolve_open_behavior` **之前**插入一个调用，逻辑放在新文件 `crates/zed/src/zed/fork_open_target.rs` 里，上游文件只加几行：

1. 判断上面「什么时候弹出选择」的条件，不满足就返回 `None`，走上游原逻辑。
2. 收集窗口列表，发 `PromptOpenTarget`，等 `SetOpenTarget`。
3. 结果：
   - `NewWindow` → `open_behavior = AlwaysNew`，后面照常走 `open_workspaces`。
   - `Window(id)` → `open_behavior = ExistingWindow`，并把对应的 `WindowHandle<MultiWorkspace>` 作为 `requesting_window` 传给 `open_workspaces`（这个函数要加一个参数，覆盖 `open_options_for_behavior` 算出来的 `requesting_window`）。
   - `Cancel` 或连接断开 → 不打开任何东西，回 `Exit { status: 130 }`。
4. 窗口在选择期间被关掉了（按 id 找不到）：在 CLI 输出一行错误，退出码 1，不自动改成新开窗口，避免出现意料之外的窗口。

**`requesting_window` 的一个坑**：`workspace::open_paths` 里只有在 `requesting_window` 为空时，才会执行「打开侧边栏或 `retain_active_workspace`」这段逻辑，这段逻辑负责把窗口当前的项目固定在窗口里，防止它被新项目替换掉。我们传了 `requesting_window`，就要在调用前自己对目标窗口执行同样的操作（`auto_open` 时 `open_sidebar`，否则 `retain_active_workspace`），再把目标窗口 `activate_window()`。

### 测试

在 `crates/zed/src/zed.rs` 现有的 CLI 测试（`cli_request` 辅助函数那一组）旁边加 fork 测试：

- 两个窗口、`interactive: true`、打开一个新目录：CLI 端先收到 `PromptOpenTarget`，窗口列表顺序和名字正确，有多个项目的窗口带 `other_projects`。
- 回 `Window(窗口 2)`：目录成为窗口 2 的一个新项目分组且是当前项目，窗口 1 没变，窗口 2 原来的项目还在。
- 回 `NewWindow`：窗口数加一。
- 回 `Cancel`：什么都没打开，退出码 130。
- `interactive: false`、传了 `-n`、路径已在某个项目里、只打开文件：都不发提示。
- 回一个不存在的窗口 id：退出码 1，没有新窗口。

手动验证：在终端里 `zed ~/某个新目录`，分别选新窗口、选第二个窗口、按 esc；再执行 `zed -e .` 和 `echo | zed .`，确认没有弹选择。

## 二、侧边栏项目多选与复制路径

### 目标

侧边栏里的项目标题行（`ListEntry::ProjectHeader`）支持像 Finder 一样多选，然后一次性复制这些项目的绝对路径或名字。

### 选择方式

| 操作 | 现在（fork H18） | 改成 |
|---|---|---|
| 单击标题 | 切到该项目 | 不变：切到该项目，同时清空多选 |
| ⌘-单击标题 | 展开/折叠 | **加入/移出多选**（Finder 的 ⌘-单击） |
| ⇧-单击标题 | 无 | **从锚点到这一行连续选中** |
| 按住鼠标在标题行上拖动 | 无 | **拖过的范围连续选中**，松开后不切换项目 |
| 点击标题左侧的折叠箭头 | 和单击标题一样 | **展开/折叠**（⌘-单击原来的功能挪到这里） |
| `esc` | 无 | 清空多选 |

- 只有项目标题行能被多选，线程行、终端行不参与，拖动经过这些行时跳过。
- 多选记的是 `ProjectGroupKey`，不记行号，所以列表重排、折叠展开以后选择状态不会错位；分组被移除时同时把它从多选里删掉。
- 锚点：最近一次单击或 ⌘-单击的那一行；⇧-单击和拖动都以它为起点。
- 选中的行用列表通用的选中背景色（`ghost_element_selected`），和当前项目的高亮能区分开。
- ⌘-单击、⇧-单击和拖动都不切换项目，并把键盘焦点留在侧边栏上，这样紧接着按 `⌘C` / `⌘⌥C` 就能复制。

折叠箭头现在只在悬停或获得焦点时显示，把它从普通图标改成可点击的 `IconButton`，点击时 `stop_propagation`，不触发整行的单击。左右方向键展开/折叠的行为保持不变。

**拖动多选的实现**：标题行 `on_mouse_down(Left)` 记录拖动起点；每个标题行的 `on_mouse_move` 在 `event.pressed_button == Some(Left)` 且起点不是自己时，把多选设成起点到当前行的范围，并标记「已经拖动过」；列表容器上的 `on_mouse_up` 清掉起点。整行的 `on_click` 发现「已经拖动过」就不切换项目（拖出去再拖回起点那一行时 `on_click` 仍会触发，所以要靠这个标记判断）。

### 复制

新增两个 action，放在侧边栏已有的 `agents_sidebar` 命名空间：

- `agents_sidebar::CopyProjectPath`：复制绝对路径。
- `agents_sidebar::CopyProjectName`：复制项目名（`display_name`，和标题显示的一样）。

复制哪些项目：

1. 有多选时，按列表顺序复制所有选中的项目。
2. 没有多选时，复制键盘选中（`selection`）的那一行所在的项目。
3. 两者都没有时什么都不做。

内容格式：

- 多个项目之间用换行分隔，最后一行后面不加换行。
- 一个项目有多个根目录时（`path_list()` 有多个路径），每个根目录单独一行。
- 远程项目只复制远程机器上的路径，不加 `ssh: 主机` 前缀，这样可以直接粘到远程终端里用。

右键菜单和 `…` 菜单里加「Copy Path」「Copy Name」两项，放在「Remove」上面。右键的那一行属于多选范围时，作用于所有选中的项目（Finder 的规则）；不属于时只作用于这一行，并清空多选。

### 快捷键

放在 `fork/keymaps/default-macos.json`：

```json
{
  "context": "ThreadsSidebar && not_searching",
  "bindings": {
    "cmd-c": "agents_sidebar::CopyProjectName",
    "cmd-alt-c": "agents_sidebar::CopyProjectPath"
  }
}
```

`⌘⌥C` 复制完整路径，和项目面板的「复制路径」一致；`⌘C` 复制项目名。侧边栏里的项目不能被粘贴成文件，`⌘C` 没有项目面板里「复制文件本身」的含义，可以拿来复制名字。不绑 `⌘⌥⇧C`。

搜索框（`searching`）和重命名输入框（`editing`）里 `⌘C` 仍然是编辑器的复制，因为它们的 `Editor` 上下文更深，优先级更高。

**一个限制**：普通单击会切到那个项目，焦点会跟着跑到编辑区，这时按 `⌘C` / `⌘⌥C` 走的是编辑器的快捷键，不是复制项目。只想复制单个项目时，用 ⌘-单击选中它再按快捷键，或者用右键菜单。我没有把单击改成「只选中、不切换」，因为单击切项目是 11 号文档里专门改的、最常用的操作。

### 改动位置

都在 `crates/sidebar/src/sidebar.rs`（挂钩），加 `// FORK:` 注释：

- `Sidebar` 结构体加多选状态（`selected_groups`、锚点、拖动起点、是否拖动过）。
- `render_project_header`：`on_click` 按修饰键分支；加 `on_mouse_down` / `on_mouse_move`；折叠箭头改成可点击的按钮；选中时的背景色。
- 右键菜单和 `…` 菜单里加两项。
- 注册两个新 action 和 `esc` 清空多选（`esc` 对应的 `menu::Cancel` 已经有处理函数，在里面先清多选，多选为空时再执行原逻辑）。
- 列表重建（项目分组被移除）时清理 `selected_groups`。

新 action 用 `actions!(agents_sidebar, [...])` 定义，在 sidebar 里已有的同名宏调用里追加。

### 测试

放在 `sidebar_tests.rs` 末尾 fork 那一段：

- ⌘-单击 A、C：多选是 A、C，当前项目不变，折叠状态不变。
- 单击 A 后 ⇧-单击 C：多选是 A、B、C。
- 单击会清空多选并切换项目。
- 点击折叠箭头：展开/折叠，不切换项目，不改变多选。
- 多选 A、C 后执行 `CopyProjectPath`：剪贴板内容是两个路径，用换行分隔；`CopyProjectName` 同理。
- 有多个根目录的项目，每个根目录一行。
- 没有多选、只有键盘选中时复制这一行的项目；两者都没有时剪贴板不变。
- 移除一个已选中的分组后，多选里不再有它。
- `esc` 清空多选。

拖动多选在测试里用 `simulate_mouse_down` / `simulate_mouse_move` 能测到就测；测不了就放进手动验证。

手动验证：拖动选中三个项目后 `⌘⌥C`，粘到终端里看是不是三行绝对路径；再按 `⌘C`，看是不是三行项目名；右键其中一行选「Copy Name」；⌘-单击后确认没有切换项目；点击折叠箭头能展开和收起。

## 已确认取舍

1. **⌘-单击的含义**：从「展开/折叠」改成「加入/移出多选」，展开/折叠挪到折叠箭头上。理由是你基本不用线程，展开/折叠很少用到，⌘-单击多选是 Finder 和项目面板共同的习惯。
2. **复制快捷键**：`⌘⌥C` 复制完整路径，`⌘C` 复制项目名。
3. **CLI 选择不加开关**：满足条件就弹；不想弹时用 `-n` / `-e` 跳过。
