# 10. Markdown 预览 Vditor 排版

> 本仓库是 zed-industries/zed 的个人 fork。整体设计见 `0.整体设计.md`。

## 目标

cweijan/vscode-office 的 Markdown 预览观感好，它用的是 [Vditor](https://github.com/Vanessa219/vditor)。Vditor 是一套浏览器端的
TypeScript WYSIWYG 编辑器，跑在 VS Code 的 webview 里，外观由两份样式表决定：

- `_markdown.scss` —— 结构（字号阶梯、间距、缩进、表格形态）
- `src/css/content-theme/{light,dark}.css` —— 颜色

Zed 的 `markdown_preview` 是 `pulldown-cmark` 解析 + GPUI 原生绘制，没有 CSS
引擎，也没有可嵌入的 webview（`crates/gpui_web` 是 WASM 目标）。所以 JS 搬不
进来，但**排版可以逐条翻译**：Vditor 的样式本身就是 GitHub 风格，和
`MarkdownStyle::with_preview_overrides` 想要的效果属于同一套语言系统，差异只在
细节。

## 设置

```json
{
  "fork": {
    "markdown_preview": { "style": "vditor" }
  }
}
```

- `fork.markdown_preview.style`：`"zed"`（默认，上游观感）或 `"vditor"`。
  改设置立即生效，不用重启（`SettingsStore` 变更后 `cx.refresh_windows()`）。

## 实现

代码在 `crates/fork_markdown_preview/`（新 crate，不会和上游冲突）。上游只有
两个挂钩（H13、H14）。

### 翻译过来的值

| 元素 | Vditor | 上游 Zed |
|---|---|---|
| 正文字号 / 行高 | 16px / 1.5 | rem 基准 / 1.5 |
| 标题字号 | 1.75 / 1.55 / 1.38 / 1.25 / 1.13 / 1em | 1.75 / 1.4 / 1.2 / 1.0 / 0.875 / 0.85rem |
| 标题下边框 | h1、h2 有，其余无 | h1、h2 有 |
| 标题上下间距 | 24px / 16px | 16px / 8px（h1 无上边距） |
| 段落间距 | 16px | 16px |
| 列表缩进 | 2em | 0.625rem（10px） |
| 列表符号 | disc → circle → square 逐级 | 固定 `•` |
| 列表项间距 | 0.25em | 4px |
| 表格外框 | 无 | 1.5px 圆角外框 |
| 表格单元格 | `1px solid`，`6px 13px` 内边距 | 单侧 1px，`10px 4px` |
| 表格斑马纹 | 表体交替（表头不算） | 奇数行，含表头行 |
| 代码块 | `0.5em` 内边距，5px 圆角 | 8px 内边距，6px 圆角 |
| 行内代码 | 85% 字号，3px 圆角 | 0.875rem |
| 引用块左边框 | 0.25em | 4px |
| 分隔线 | 2px | 1px |
| 链接 | 深色主题才染色 | 带底色和下划线 |

颜色按明暗主题分别取：浅色用 `#eaecef` 边框、`#fafbfc` 表头；深色用
`#d1d5da` 边框、`#2f363d` 表头、`#24292e` 条纹。属于主题语义色的（正文、次要
文字、编辑器背景）直接复用当前主题，不写死。

### 挂钩

- **H13** `crates/markdown_preview/src/markdown_preview_view.rs`：把
  `render_markdown_element` 里内联构造 `MarkdownStyle` 的三行换成
  `fork_markdown_preview::preview_markdown_style(preview_theme.as_ref(), window, cx)`。
  用一层函数包住而不是内联 `if`，样式翻译全留在 fork 里。同文件
  `Cargo.toml` 加依赖。
- **H14** `crates/markdown/src/markdown.rs`：`MarkdownStyle` 加 7 个布局字段
  （`list_layout`、`table_layout`、`heading_layout`、`code_block_layout`、
  `inline_code_layout`、`block_quote_layout`、`rule_height`），并把标题边距、
  列表缩进与符号、表格边框与斑马纹、代码块与 chip 圆角、引用块左边框、分隔线
  高度改成读这些字段。

**字段默认值严格等于上游原值**，所以不设置时渲染结果和上游完全一致：`markdown`
的 189 个测试、`markdown_preview` 的 38 个测试都原样通过。这一点是刻意的——
`MarkdownStyle` 有 37 处结构体字面量，只有 3 处不带 `..` 展开（定义处和两处
`impl`），加字段不会波及 `agent_ui`、`git_ui`、`repl`。

## 没做的

- **行内代码的内边距**。浏览器的 `padding: .2em .4em` 在 GPUI 文本布局里没有
  位置：`paint_code_chips` 的注释说明布局不给 chip 预留空间，加宽会吃掉相邻
  单词的间隙。只保留了圆角和字号。
- **WYSIWYG 编辑**。在预览里直接改字是 Vditor 的核心能力，GPUI 下没有对应
  机制，也不在“移植排版”的范围内。
- **markdown-it 的扩展语法**。Vditor 经 markdown-it 支持 Obsidian wikilink、
  front-matter、KaTeX 等；`pulldown-cmark` 不支持的部分不会因为换样式出现。
- **字体族**。Vditor 写死 `"Helvetica Neue", ...`，这里沿用用户自己的预览
  字体设置（`markdown_preview.font_family`），不覆盖。
- 没加到设置界面（Settings UI），只能在 `settings.json` 里改。

## 测试

`fork_markdown_preview::tests`：

- 六级标题的字号和字重都对，h1/h2 画下边框、h3 不画。
- 列表符号是 disc/circle/square，缩进是 2em。
- 表格没有外框，单元格线与表头底色存在。
- 代码块 / 行内代码圆角、引用块左边框、分隔线高度。
- 上游默认值未被污染（`MarkdownStyle::default()` 这些字段仍是空的）。
- 设置从 `"vditor"` 切到 `"zed"` 能正确往返。

另外目视验证过：One Dark 和 One Light 下分别切换 `"vditor"` / `"zed"`，
标题阶梯、列表符号、表格形态、斑马纹都按预期变化。
