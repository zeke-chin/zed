# 回归清单

每次用 `sync-upstream.sh` 同步、或打包前，手动过一遍。每项一两分钟。先让 `cargo test -p fork_ext -p fork_copy_anchor -p fork_json_explorer -p fork_windsurf` 通过（脚本已跑），这里只列自动测试覆盖不到的手动项。

运行的应用应是本次构建的 Zed Dev（「关于」里的版本带 `-fork`），并确认三个功能的 `enabled` 都是 `true`。

## 准备

- [ ] 「Zed > 关于」：通道是 Dev，完整版本里带 `-fork` 标记
- [ ] 官方 `Zed.app` 能同时运行，互不影响数据目录，没有更新提示

## Copy Anchor

- [ ] 在文件里选中几行代码，`cmd-c`，粘贴到别处：内容带文件路径和行号锚点，行号与实际代码行一致
- [ ] 选区首尾有空行时，行号仍然对得上
- [ ] 状态栏有模式标识；点击或按 `ctrl-\ ctrl-\` 切换模式，剪贴板在「带锚点」和「原文」之间互换，不用重按 `cmd-c`
- [ ] 切换后设置里的 `fork.copy_anchor.context_mode` 跟着变
- [ ] 在 `keymap.json` 把 `copy_anchor::Copy` 改绑到别的键能生效，并能把 `cmd-c` 恢复成原生复制
- [ ] 开启 Vim 模式，`y` 等 Vim 复制不受影响
- [ ] 菜单栏「编辑 > 复制」和右键菜单里的「复制」仍是原生复制（不带锚点）

## JSON Explorer

- [ ] 新建空文件，粘贴一段压缩的 JSON：语言变为 JSON，内容已格式化；撤销一次回到粘贴前的原始文本
- [ ] 在 JSON 文件里 `cmd-;`：来回切换两次，内容与最初一致
- [ ] 粘贴 Python dict：默认不改动并出现提示，`cmd-;` 后转成 JSON
- [ ] 粘贴普通文本或 Python 源码：内容和语言都不变
- [ ] Hover 一个嵌套的 JSON 字符串字段：悬浮窗显示解析后的类型和内容，顶部和底部有可点击的链接
- [ ] 点悬浮窗里的链接：右侧分栏打开对应文档；在新文档里继续嵌套解析也可以
- [ ] JSON 文件里原有的 LSP Hover（schema 说明）仍然显示
- [ ] 粘贴一个约 10 MB 的 JSON，界面不卡死
- [ ] 在 Rust 文件里点文档悬浮窗中的普通链接（网址、文件链接），行为与官方一致

## Windsurf

前提：已通过 `windsurf: import api key` 或手动填写配置了密钥。

- [ ] 在 Rust、TypeScript 或 Python 文件里输入，出现编辑预测，`Tab` 接受后文本正确
- [ ] 把一个变量名改掉，后面旧名字处出现修改预测，以 diff 预览显示
- [ ] 触发一次跳转预测（阶段 5 完成后）并能接受
- [ ] 没有任何编辑时不发请求；含中文和 emoji 的行里编辑位置没有偏移
- [ ] 执行 `windsurf: show last request`：能看到最近一次请求和服务端返回的提示词，密钥和令牌已打码
- [ ] 断网后继续输入：编辑器不卡顿，状态栏显示对应原因
- [ ] 用原生后端时，`pgrep -fl language_server` 没有结果
- [ ] 用 LS 桥接后端时（阶段 8，启用了才查）：退出 Zed 后 `pgrep -fl language_server` 没有残留进程

## 功能全关

在用户设置里把 `fork.copy_anchor.enabled`、`fork.json_explorer.enabled`、`fork.windsurf.enabled` 都改成 `false`，不重启：

- [ ] `cmd-c` 是原生复制；Copy Anchor 的状态栏项消失，`ctrl-\ ctrl-\` 无效
- [ ] 粘贴 JSON 不触发识别，`cmd-;` 没有绑定，Hover 没有追加内容
- [ ] Windsurf 不发任何网络请求，状态栏里没有它的项；官方的编辑预测 provider 设置照常生效
- [ ] 改回 `true`，三个功能立即恢复，不用重启
