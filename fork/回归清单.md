# 回归清单

每次用 `sync-upstream.sh` 同步、或打包前，手动过一遍。每项一两分钟。先让 `cargo test -p fork_ext -p fork_copy_anchor -p fork_json_explorer -p fork_windsurf` 通过（脚本已跑），这里只列自动测试覆盖不到的手动项。

运行的应用应是本次构建的 Zed Dev（「关于」里的版本带 `-fork`），并确认三个功能的 `enabled` 都是 `true`。

## 准备

- [ ] 「Zed > 关于」：通道是 Dev，完整版本里带 `-fork` 标记
- [ ] 官方 `Zed.app` 能同时运行，互不影响数据目录，没有更新提示

## Copy Anchor

- [ ] 在文件里选中几行代码，`cmd-c`，粘贴到别处：内容带文件路径和行号锚点，行号与实际代码行一致
- [ ] 选区首尾有空行时，行号仍然对得上
- [ ] 状态栏有模式标识；点击或按 `ctrl-\ ctrl-\` 切换模式，剪贴板在「带锚点」和「原文」之间互换，不用重按 `cmd-c`
- [ ] 切换后设置里的 `fork.copy_anchor.context_mode` 跟着变
- [ ] 在 `keymap.json` 把 `copy_anchor::Copy` 改绑到别的键能生效，并能把 `cmd-c` 恢复成原生复制
- [ ] 开启 Vim 模式，`y` 等 Vim 复制不受影响
- [ ] 菜单栏「编辑 > 复制」和右键菜单里的「复制」仍是原生复制（不带锚点）

## JSON Explorer

- [ ] 新建空文件，粘贴一段压缩的 JSON：语言变为 JSON，内容已格式化；撤销一次回到粘贴前的原始文本
- [ ] 在 JSON 文件里 `cmd-;`：来回切换两次，内容与最初一致
- [ ] 粘贴 Python dict：默认不改动并出现提示，`cmd-;` 后转成 JSON
- [ ] 粘贴普通文本或 Python 源码：内容和语言都不变
- [ ] Hover 一个嵌套的 JSON 字符串字段：悬浮窗显示解析后的类型和内容，顶部和底部有可点击的链接
- [ ] 点悬浮窗里的链接：右侧分栏打开对应文档；在新文档里继续嵌套解析也可以
- [ ] JSON 文件里原有的 LSP Hover（schema 说明）仍然显示
- [ ] 粘贴一个约 10 MB 的 JSON，界面不卡死
- [ ] 在 Rust 文件里点文档悬浮窗中的普通链接（网址、文件链接），行为与官方一致

## Windsurf

前提：已通过 `windsurf: import api key` 或手动填写配置了密钥。

- [ ] 在 Rust、TypeScript 或 Python 文件里输入，出现编辑预测，`Tab` 接受后文本正确
- [ ] 把一个变量名改掉，后面旧名字处出现修改预测，以 diff 预览显示
- [ ] 触发一次跳转预测（阶段 5 完成后）并能接受
- [ ] 没有任何编辑时不发请求；含中文和 emoji 的行里编辑位置没有偏移
- [ ] 执行 `windsurf: show last request`：能看到最近一次请求和服务端返回的提示词，密钥和令牌已打码
- [ ] 断网后继续输入：编辑器不卡顿，状态栏显示对应原因
- [ ] 用原生后端时，`pgrep -fl language_server` 没有 Zed 启动的进程（Devin.app 自己的 LS 不算：它的参数里 `--database_dir` 在 `~/.codeium` 下）

### Windsurf：LS 桥接后端

前提：本机装了 Devin.app（或设置了 `fork.windsurf.language_server_path`）。把 `fork.windsurf.backend` 改为 `"language_server"`，不重启。Zed 启动的 LS 参数里 `--database_dir` 指向 Zed 数据目录下的 `windsurf-ls/database`，用 `pgrep -fl windsurf-ls` 只看它，不要动 Devin 自己的 LS。

- [ ] 第一次输入后状态栏短暂显示「starting…」，LS 起来后连续输入出现修改预测，`Tab` 接受正确；跳转预测显示为「Jump to <文件>」，接受后光标跳过去并出现那里的修改预测
- [ ] Devin.app 没开的时候同样可用
- [ ] 打开两个窗口编辑：`pgrep -fl windsurf-ls` 只有一个进程
- [ ] 状态栏菜单有「Restart Language Server」和「Show Language Server Version and Path」；前者重启后 pid 变化，后者显示路径、版本、数据目录和日志文件
- [ ] 按 pid `kill` 掉 Zed 启动的 LS，继续输入：自动起新的 LS，再输入一两个字符后恢复预测
- [ ] 把 `fork.windsurf.backend` 改回 `"native"`：几秒内 `pgrep -fl windsurf-ls` 没有结果，原生预测照常
- [ ] `fork.windsurf.language_server_path` 填一个不存在的路径：状态栏显示「language server not found」，编辑器不卡；改回空值后恢复
- [ ] 退出 Zed 后 `pgrep -fl windsurf-ls` 没有残留；用 `kill -9` 结束 Zed 进程，LS 也在一秒内退出
- [ ] SSH 远程项目里状态栏显示「not in remote projects」，不发请求
- [ ] `~/.codeium` 下没有新出现 Zed 启动的 LS 写的文件（它的数据在 Zed 数据目录的 `windsurf-ls/` 下）

## Git 面板 VS Code 布局

用户设置里加 `"git_panel": { "dock": "left" }` 和 `"fork": { "git_panel": { "layout": "vscode" } }`：

- [ ] Git 面板在左边，从上到下是 CHANGES（提交框、Commit 按钮、文件列表）和 GRAPH，没有 Changes / History 标签栏
- [ ] 提交框从一行开始，多行输入时变高；点 ✦ 生成提交信息、`cmd-enter` 提交都正常；提交后 GRAPH 第一行是新提交
- [ ] 有合并提交的仓库里，GRAPH 的连线和分叉、汇合位置正确；当前分支徽标带 ✓，同名远程分支显示成云图标
- [ ] 点 CHANGES、GRAPH 标题能折叠和展开；拖动分隔条能调整高度，双击恢复默认
- [ ] 点历史里的一行打开提交详情；点 Changes 里的文件后上下键在 Changes 里移动，点历史后上下键在历史里移动
- [ ] GRAPH 标题右侧的 Fetch/Push 按钮可用，图标按钮在编辑区打开完整 Git Graph
- [ ] 把 `layout` 改成 `"tabs"`，不重启：恢复上游的标签页布局，提交区回到底部

## 功能全关

在用户设置里把 `fork.copy_anchor.enabled`、`fork.json_explorer.enabled`、`fork.windsurf.enabled` 都改成 `false`，不重启：

- [ ] `cmd-c` 是原生复制；Copy Anchor 的状态栏项消失，`ctrl-\ ctrl-\` 无效
- [ ] 粘贴 JSON 不触发识别，`cmd-;` 没有绑定，Hover 没有追加内容
- [ ] Windsurf 不发任何网络请求，状态栏里没有它的项；官方的编辑预测 provider 设置照常生效
- [ ] 改回 `true`，三个功能立即恢复，不用重启
